# Приёмка MMU и защиты памяти, 2026-10-03

Все три оставшихся CPU-пункта [этапа 2](../docs/02_MEMORY_MMU.md) пройдены
на готовом `laix/build/laix.img`, Darwin arm64. Код, прошивка и эмулятор
при проверке не собирались. `probe_mmu_cpu.py` выполнил 13 сценариев;
каждый закончился ожидаемым аппаратным page fault и полным panic dump,
exit 254. Успешные доступы до завершающего fault проверены отдельно.

## Метод

Monitor меняет только fixture-данные и сохранённые IRET-контексты временной
машины. CPU исполняет существующие `allocPage`, `mmuCreateAddressSpace`,
`mapPage`, `unmapPage`, `setPagePermissions`, `mmuSwitchAddressSpace`,
`mmuActivateKernel` и `memcpy`. Таблицы страниц изменяет только MMU API.
Load/store выполняются настоящими LW/SW из готового `memcpy`, а не чтением
виртуальной памяти через monitor. Между вызовами используется ожидаемый
BREAK и настоящий IRET; они не инвалидируют TLB.

Точки останова фиксируют исполнение MMU FENCE, TLBI.ALL и MTCR PTBR.
Проверено, что TLBI.ALL следует после исполненного FENCE, а PTBR меняется
после TLBI.ALL. После map/unmap/protect проверяется наличие выполненной
инвалидации. До изменения отображений CPU читает и записывает проверяемый VA.
Перед проверкой ASID оба каталога заполняются, затем прогреваются оба старых VA;
после этого каталогов не редактируют. Переключение 7→0→7 проверяет повторную
выдачу ASID другому владельцу без маскировки same-ASID записью PTBR.

Для user store из RX копируются существующие байты `memcpy` в выделенный
кадр до назначения X. IRET возвращает CPU в UM с недоступным user SP;
fault обрабатывается на доверенном стеке. Для NX-проверок целевое слово —
готовая инструкция HLT (0): ошибочно разрешённое исполнение дало бы exit 0.
Все CAUSE/BADADDR/EPC, STATUS/PTBR/FCSR и 32 GPR сверяются на входе CPU в trap
и в итоговом UART-дампе. Файлы исходного образа, карты, ROM и эмулятора
сохранены без изменений; SHA-256 проверены после прогона.

## Воспроизведение и артефакты

```sh
python3 -B laix/tests/probe_mmu_cpu.py laix/build/laix.img laix/build/laix.map
```

Для одного сценария: `--case asid` (можно повторять). UART, monitor trace и
вывод эмулятора для каждого запуска находятся в
`laix/build/acceptance/mmu_cpu/`; `results.json` содержит результаты,
аргументы/ответы вызовов API и трассу инвалидаций, признак `complete` и SHA-256.
Эти исполняемые артефакты и логи лежат вне Git.

что уже реализованы загрузка Task, syscall API или планировщик этапа 3.
