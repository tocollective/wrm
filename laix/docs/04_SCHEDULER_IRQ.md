# Этап 4. Планировщик, таймер и IRQ

[План ядра](KERNEL.md) · [Предыдущий этап](03_USER_TASK_SYSCALLS.md) · [Следующий этап](05_IPC_RIGHTS.md)

Статус: предстоит. Цель — две задачи с независимыми контекстами,
переключение сначала по yield, затем по таймеру, ожидание и завершение.
Зависимости: память и хотя бы одна работающая user-задача из этапов 2–3.

## Что сделать

### Учёт задач и добровольное переключение

- [ ] Расширить TCB: состояние, сохранённый TrapFrame, каталог/PTBR,
  ASID, границы kernel-стека, причина ожидания и код завершения.
- [ ] Определить состояния Ready, Running, Blocked, Dead и разрешённые
  переходы. Ready-задача должна быть в очереди ровно один раз.
- [ ] Реализовать ограниченную таблицу задач и очередь round-robin;
  для начала одной аппаратной нити и одного потока на задачу достаточно.
- [ ] Добавить syscall yield: сохранить контекст текущей задачи,
  продвинуть её EPC и выбрать следующую Ready-задачу.
- [ ] Подготовить первые синтетические кадры задач и общий путь их восстановления.
- [ ] Определить интерфейс выбора контекста. Сейчас trapDispatch возвращает
  Void, а эпилог читает текущий sp; для другой задачи нужен возврат указателя
  на выбранный кадр или отдельный ассемблерный путь переключения.
- [ ] При выборе задачи согласованно менять текущий TCB, PTBR/ASID,
  KERNEL_SP и границы стека; сохранять отображения пролога и обоих стеков.
- [ ] Переключать каталог и выполнять TLB-протокол до возврата в выбранный
  контекст; не терять пользовательские tp, ra, sp и FCSR.
- [ ] Не возвращать завершённую задачу в Ready; освобождать её kernel-стек
  и каталог после завершения их использования CPU.

Для syscall сохранённый EPC продвигается на 4. Для IRQ аппаратный EPC уже
указывает на следующую невыполненную инструкцию: дополнительно сдвигать
его нельзя. Это разные причины входа в один планировщик.

### Таймер и обработчик IRQ

- [ ] Разделить CAUSE=0 и синхронные исключения; выяснять IRQ через PIC CLAIM.
- [ ] Реализовать ветку таймера до разрешения STATUS.IE/PIC ENABLE.
- [ ] Вычислять период из частоты таймера/boot CLOCK, а не из константы
  предполагаемой скорости эмулятора; запретить период 0 в настройках.
- [ ] Настроить TIMER RELOAD/CONTROL и включить только IRQ 2 в PIC.
- [ ] Снимать EXPIRED записью 1 в TIMER STATUS перед возвратом; чтение
  PIC CLAIM само не очищает запрос. Отдельного PIC EOI на WRM нет.
- [ ] Выбирать новую задачу по истечению кванта; хранить очереди под
  защитой от прерываний и согласовать порядок завершения/пробуждения.
- [ ] Для неожиданного IRQ определить маскирование и диагностику;
  не допускать бесконечного возврата на неизменённую asserted линию.
- [ ] Включать пользовательские IRQ через PIE при IRET только после
  готовности ветки. Для idle определить корректный supervisor IE/EXL.
- [ ] Сохранить невложенный обработчик с EXL=1. Поддержка вложенности
  потребует отдельного изменения низкого TRAP_SAVED_R1 и сохранения
  управляющих регистров, а не просто установки IE внутри обработчика.

- [ ] Добавить ожидание устройства с deadline по `COUNT` таймера
  (`waitUntil`, чтение HI–LO–HI) и перевести на него ожидания `BUSY`
  видеокарты, `DONE` диска в кеше глифов и `FRAME` в консоли. Таймаут —
  диагностируемый отказ драйвера с сообщением в UART, а не зависание ядра.
  Сейчас эти ожидания ограничены только контрактом устройств.

EXPIRED хранит наличие события, а не число пропущенных периодов.
Для прошедшего времени использовать свободный COUNT с согласованным
чтением старшей/младшей половины; не считать каждый IRQ точным секундомером.

### Ожидание, idle и завершение

- [ ] Добавить перевод Running → Blocked и пробуждение Blocked → Ready,
  пока хотя бы для тестового события; предусмотреть будущие IPC-очереди.
- [ ] Создать отдельную idle-задачу с доверенным стеком и wfi().
- [ ] Сделать проверку очереди и переход к WFI без потери события
  пробуждения; спящий CPU должен иметь настроенный источник IRQ.
- [ ] При exit или user fault завершать только соответствующую задачу;
  другой пользовательский контекст продолжает работать.
- [ ] При отсутствии задач выбрать idle/явное завершение теста, а не
  восстанавливать освобождённый кадр.

## Что проверить

- [ ] Две задачи поочерёдно работают через yield с предсказуемым порядком.
- [ ] Без yield обе задачи получают CPU благодаря таймеру; одна busy-loop
  не удерживает процессор навсегда.
- [ ] Проверить десятки тысяч переключений с разными GPR, FCSR и tp/TLS.
- [ ] Одинаковый user-адрес в двух каталогах содержит разные данные;
  переключение не оставляет старую TLB-трансляцию.
- [ ] В очереди нет дублей; Blocked/Dead никогда не исполняются.
- [ ] Пробуждение работает до, во время и после решения перейти в idle.
- [ ] Отсутствие Ready-задач приводит к WFI, событие возвращает выполнение.
- [ ] Прерывание приходит на корректный kernel-стек выбранной задачи;
  current TCB, PTBR и низкие слова стека соответствуют друг другу.
- [ ] После IRQ выполнение продолжается с исходного аппаратного EPC.
- [ ] EXPIRED действительно снят; нет непрерывного повторного IRQ без нового периода.
- [ ] Exit/fault одной задачи не останавливает другую и не оставляет
  утечек страниц, ожидающих событий или указателей на её стек.
- [ ] Пройти прежние boot/trap/user-тесты с включённым таймером.

## Когда этап готов

Две изолированные задачи работают и с yield, и с вытеснением;
ожидающая задача не занимает CPU, idle просыпается, завершение одной
задачи не разрушает другую. Приоритеты, SMP и real-time политики позже.
Контракты — [IRQ и IRET](../../docs/INSTRUCTIONS.md#interrupts) и
[PIC/таймер](../../docs/SPECIFICATION.md).
