# Этап 2. Физическая память и MMU

[План ядра](KERNEL.md) · [Предыдущий этап](01_BOOT_TRAPS.md) · [Следующий этап](03_USER_TASK_SYSCALLS.md)

Статус: начат. Цель — управлять физическими страницами и создавать
адресные пространства, сохраняя защиту ядра и владение памятью.

## Что уже есть

[`memory.m`](../src/memory.m) резервирует память от нуля до округлённого
вверх `__bss_end`; `physicalPageAvailable()` проверяет допустимость страницы.
Эта функция не выделяет страницу и не учитывает, была ли она уже выдана.

[`mmu.m`](../src/mmu.m) создаёт supervisor identity map RAM, VRAM и MMIO
с W^X и включает MMU. Права без `U`: `.text` — RX, `.rodata` — R, страница
boot info со словами входа, `.data`, `.bss` и остальная RAM — RW без X.
Страница 0 (NULL), бывший стек firmware `0x2000…0xFFFF` и guard page не
отображаются. `start.asm` выравнивает `.rodata` и `.data` по страницам;
ядро вместе с BSS должно помещаться в первые 4 МиБ, которые отображены
постранично, иначе `mmuInit()` отказывает.
`mmuInitAddressSpace()` копирует шаблон каталога в допустимую неактивную
страницу; вызывающий код ещё должен обеспечить владение этой страницей.

## Что сделать

### Распределитель физических страниц

- [x] Читать размер RAM из проверенного boot info и ограничивать арифметику.
- [x] Зарезервировать низкую память, образ, всю BSS, стек, guard и начальные таблицы.
- [ ] Выбрать bitmap или список свободных страниц по 4 КиБ; сначала достаточно bitmap.
- [ ] Разместить метаданные распределителя в зарезервированной памяти и
  включить их в учёт до выдачи первой страницы.
- [ ] Реализовать `allocPage()` с явным результатом нехватки памяти и `freePage()`.
- [ ] Учитывать занятость и владельца/назначение; запрещать повторную
  выдачу, освобождение резервов и double free.
- [ ] Обнулять страницы перед передачей новой пользовательской задаче.
- [ ] Возвращать уже выданные страницы при частичной ошибке создания задачи.
- [ ] Защитить изменение учёта от прерываний до включения вытеснения.

Большой heap пока не нужен: таблицы задач и объектов можно ограничить
заранее, а переменную память выдавать страницами.

### Таблицы страниц и отображения

- [x] Выравнивать каталоги/таблицы на 4 КиБ; использовать страницы 4 КиБ
  и допустимые superpage-отображения 4 МиБ.
- [x] Включить MMU с рабочими отображениями кода, стека и UART.
- [x] Сделать guard page недоступной без алиаса её физической страницы.
- [x] Подготовить шаблон общих supervisor-отображений для нового каталога.
- [ ] Выделять каталог и промежуточные таблицы через распределитель,
  а не только проверять диапазон физического адреса.
- [ ] Определить диапазоны виртуальных адресов ядра и пользовательских задач.
  Сохранять низкие слова входа `0x1FF0`–`0x1FFC` supervisor-only и не
  отображать страницу 0 (NULL).
- [ ] Добавить `mapPage`, `unmapPage` и изменение разрешений; проверять
  выравнивание, переполнение диапазонов, владение и конфликт отображения.
- [ ] Не разрешать U-алиас резервов ядра, guard, таблиц страниц или чужой памяти.
- [ ] При необходимости разделять текущие superpage на таблицы 4 КиБ.
- [ ] Выполнять FENCE/TLBI по ISA после изменения отображений; отдельно
  определить переключение PTBR и повторное использование ASID.
- [ ] Уничтожать адресное пространство без освобождения общих таблиц ядра
  и без повторного освобождения разделяемых страниц.

На WRM таблицы содержат физические адреса, а IVEC и стек после включения
MMU используют виртуальные. Общие отображения должны позволять выполнить
весь вход/выход обработчика при любом выбранном каталоге.

### Разрешения секций и алиасы

- [x] Получить точные границы `.text`, `.rodata`, `.data`, `.bss` из
  компоновки; разделить секции с разными правами по границам страниц
  (по исходникам: `start.asm`, `kernelLayoutValid()`, `test_memory.py`).
- [x] Отобразить код RX, константы R, изменяемые данные и стеки RW без X
  (по исходникам; runtime — образы `text_write` и `data_exec`).
- [ ] Оставить MMIO и VRAM без U и X до явной выдачи прав сервису.
- [ ] Удалить writable-алиасы защищённого кода и executable-алиасы данных:
  W^X относится ко всем отображениям одной физической страницы.
- [ ] Описать доверенное отображение для работы ядра с физической памятью;
  нынешний общий RWX identity map не оставлять окончательным.

## Что проверить

Подтверждённая часть:

- [x] `test_memory.py` проверяет резервирование, округление границ и
  построение текущих таблиц без генерации кода.
- [x] Готовый `stack_guard.img` даёт store page fault с ожидаемыми
  CAUSE/BADADDR/EPC и кодом 254.

Для завершения этапа:

- [ ] Выдать все свободные страницы: адреса уникальны, выровнены и вне резервов.
- [ ] После исчерпания вернуть ошибку без повреждения bitmap; после
  освобождения страница снова выдаётся ровно одному владельцу.
- [ ] Отвергнуть double free, невыровненный адрес и адрес вне RAM.
- [ ] Новая пользовательская страница не содержит данные прежнего владельца.
- [ ] Повторный map, неверные флаги и запрещённый U-алиас не изменяют таблицы.
- [ ] Map/unmap/remap меняет доступ CPU после нужной инвалидации TLB.
- [ ] Переиспользование ASID не открывает старые отображения другой задачи.
- [ ] Запись в код/константы и исполнение из данных дают соответствующие faults.
  Подготовлены образы `tests/text_write.m` (CAUSE=10) и `tests/data_exec.m`
  (CAUSE=8); они ещё не собирались и не запускались.
- [ ] Ошибка создания каталога и его уничтожение не теряют страницы.
- [ ] Проверить минимальную/максимальную RAM и неполную последнюю
  4 МиБ-область; таблицы не отображают память за концом RAM.
- [ ] Guard и защищённые секции недоступны через другой виртуальный адрес.

## Когда этап готов

Есть распределитель, управляемые отображения с проверкой владения и
разрешений, возврат памяти при ошибках и повторяемые тесты доступов на CPU.
Одного включения MMU для завершения этапа недостаточно.

Проверки — анализ исходников и запуск готовых подходящих образов.
Сборка в текущей сессии не используется как проверка.
Контракт — [MMU в ISA](../../docs/INSTRUCTIONS.md#memory-management).
