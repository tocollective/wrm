# Этап 2. Физическая память и MMU

[План ядра](KERNEL.md) · [Предыдущий этап](01_BOOT_TRAPS.md) · [Следующий этап](03_USER_TASK_SYSCALLS.md)

Статус: выполнен для одного CPU. Учёт страниц и MMU проверены по исходникам;
доступы, TLB, ASID и faults подтверждены на готовом образе через monitor.
Цель — управлять физическими страницами и создавать адресные пространства,
сохраняя защиту ядра и владение памятью.

## Что уже есть

[`memory.m`](../src/memory.m) резервирует память от нуля до округлённого
вверх `__bss_end`, затем область учёта страниц за BSS, до первой выдачи RAM.
В BSS находятся только bitmap распределителя и битовая карта инициализированных
каталогов `spaceInitialized` — по 4 КиБ для максимальных 128 МиБ RAM.
`pageOwners`, `pagePurposes`, `pageReferences` и `pageAccessReferences` — указатели на четыре массива
по одному слову на каждую полную страницу установленной RAM. Область массивов
округляется вверх до 4 КиБ: при 1 МиБ RAM она занимает 4 КиБ, при 128 МиБ —
512 КиБ. Размер и полный конец области проверяются до записи в память;
метаданные и padding не могут быть выданы или получить U-алиас. Владелец
каталога хранится в распределителе; повторять его отдельным массивом не нужно.
`physicalPageAvailable()` проверяет фактическую свободу страницы; сама проверка
не выделяет её. Повторный `memoryInit()` запрещён.

`allocPage(owner, purpose)` выдаёт физический адрес страницы 4 КиБ или
`PAGE_NONE` (0) при нехватке памяти либо неверных аргументах. Владелец —
ненулевой идентификатор, назначенный доверенным кодом ядра. Назначения:
`PAGE_KERNEL`, `PAGE_DIRECTORY`, `PAGE_TABLE`, `PAGE_USER`,
`PAGE_USER_STACK`, `PAGE_KERNEL_STACK`. Пользовательские страницы и
user-стек полностью обнуляются до возврата адреса. `freePage(address,
owner, purpose)` возвращает Bool: чужая, резервная, невыровненная,
недопустимая, уже свободная или удерживаемая MMU страница отвергается без
изменения учёта. `retainPage()`/`releasePage()` — доверенные операции ядра:
проверяют владельца/назначение, переполнение и уменьшение счётчика ниже нуля.
Доверенное supervisor-окно физической памяти само не удерживает кадры:
оно служит ядру для их обнуления, заполнения и повторного использования.
Его права для пользовательского кадра зависят от наличия X-отображений,
как описано ниже; ядро не получает исключения из общего W^X.

`allocTaskPages(owner, purposes, pages, count)` выделяет набор страниц
атомарно: при частичной нехватке памяти освобождает только выданные этим
вызовом страницы и обнуляет выходные слоты. `freeTaskPages()` с теми же
аргументами возвращает набор при более поздней ошибке подготовки задачи;
заранее проверяет весь набор, включая повторные адреса. Входные назначения
и изначально нулевые выходные слоты должны находиться в отдельных доверенных
буферах ядра вне выдаваемой RAM. Число слотов соответствует `count`.
Перед освобождением вызывающий код обязан удалить отображения и прекратить
использование каталога/стека. MMU закрепляет инициализированные каталоги и
таблицы, поэтому их нужно уничтожать через `mmuDestroyAddressSpace()`,
а не через `freeTaskPages()`. После уничтожения отдельным набором возвращают
только оставшиеся неотображённые страницы; уже освобождённые адреса
в набор не включают. Самого загрузчика и создания Task ещё нет:
этот контракт предназначен для [этапа 3](03_USER_TASK_SYSCALLS.md).

Изменения и проверки учёта сохраняют STATUS, выключают IE и восстанавливают
исходное состояние после FENCE; вложенные вызовы не включают IRQ. Это защита
для одного CPU до вытеснения, а не блокировка для SMP. Проверки доступности
и владения дают снимок; резервировать страницу нужно через `allocPage()`.

[`mmu.m`](../src/mmu.m) создаёт supervisor identity map RAM, VRAM и MMIO
с W^X и включает MMU. Права без `U`: `.text` — RX, `.rodata` — R, страница
boot info со словами входа, `.data`, `.bss` и остальная RAM — RW без X.
Страница 0 (NULL), бывший стек firmware `0x2000…0xFFFF` и guard page не
отображаются. `start.asm` выравнивает `.rodata` и `.data` по страницам;
ядро вместе с BSS должно помещаться в первые 4 МиБ, которые отображены
постранично, иначе `mmuInit()` отказывает.
Начальный каталог и таблицы всех регионов RAM выдаются распределителем,
закрепляются ссылками и получают владельца `0xFFFFFFFF`, зарезервированного
для MMU ядра. При нехватке RAM начальная выдача откатывается; MMU остаётся
выключенной. Вся RAM использует общие таблицы 4 КиБ, включая полные
регионы 4 МиБ; неполный хвост остаётся неотображённым. Стоимость таблиц —
одна страница на каждые начатые 4 МиБ RAM (до 128 КиБ при 128 МиБ RAM),
плюс каталог. Общие таблицы позволяют менять права физического окна
одновременно во всех существующих и будущих адресных пространствах.
`mmuCreateAddressSpace(owner)` выделяет каталог и возвращает физический адрес
или `PAGE_NONE`. `mmuInitAddressSpace(directory, owner)` поддерживает заранее
выданный каталог, но принимает только свежую, неактивную, незакреплённую
страницу с `PAGE_DIRECTORY`; повторная инициализация запрещена.

Виртуальное окно задач — `[0x40000000, 0xC0000000)`. Остальные адреса
принадлежат ядру: RAM отображена тождественно только до её фактического конца,
VRAM — `0xFC000000…0xFC3FFFFF`, MMIO — `0xFD000000…0xFD3FFFFF`.
Незадействованные адреса не отображаются. Во всех каталогах страница 0
отсутствует, а страница `0x1000`, включая `0x1FF0–0x1FFC`, имеет supervisor RW.

`mapPage(directory, owner, virtual, physical, permissions)`,
`unmapPage(directory, owner, virtual)` и
`setPagePermissions(directory, owner, virtual, permissions)` работают только
в окне задач и возвращают Bool. Адреса выровнены на 4 КиБ; диапазоны
проверяются через `mmuUserRangeValid(address, size)` без сложения с возможным
переполнением. Флаги — `V|U|R` с необязательным `W` либо `X`; `W|X`,
переданные `A/D/G` и резервные биты запрещены. Разрешены только страницы
этого владельца с `PAGE_USER`/`PAGE_USER_STACK`: резервы, guard, таблицы,
ядро, устройства и чужая память не получают U-алиас. Повторный map занятой
записи — ошибка; для remap сначала вызывают unmap. Аппаратные A/D сохраняются
при смене разрешений. Каждая U-запись удерживает физическую страницу.
Unmap снимает ссылку, оставляет саму страницу владельцу и освобождает пустую
промежуточную таблицу. Отказ в выделении таблицы откатывает ссылку.

W^X проверяется по физическому кадру во всех управляемых каталогах и
виртуальных алиасах, включая неактивные пространства одного владельца.
`pageAccessReferences` хранит число W- либо X-алиасов в младших 31 битах;
старший бит обозначает X. Одновременно W и X запрещены, R-алиасы допустимы
с обоими режимами и учитываются в обычном `pageReferences`. Переполнение
счётчика, конфликт при map или смене прав отвергаются до изменения таблиц
и ссылок. `PAGE_USER_STACK` никогда не получает X. Код и константы ядра,
данные ядра, guard и таблицы не могут получить пользовательский алиас.

### Доверенное физическое окно ядра

Физический адрес RAM совпадает с виртуальным адресом supervisor-окна.
Окно присутствует во всех каталогах, всегда без U; пользовательские кадры
в нём никогда не получают X. До появления X-алиасов кадр доступен ядру RW:
распределитель обнуляет его, а будущий загрузчик заполняет содержимое.
Перед публикацией первого пользовательского RX-алиаса общая PTE окна
становится R и выполняется `FENCE; TLBI.ALL`, удаляющий кешированные RW
трансляции во всех ASID. Пока остаётся хотя бы один X-алиас, окно остаётся R;
создание нового каталога использует те же таблицы и не возвращает W.

Для смены W/X сначала снимается старая пользовательская PTE и выполняется
`FENCE; TLBI.ALL`. Изменение прав окна сопровождается отдельной инвалидацией
до публикации новой пользовательской PTE; после публикации следует ещё
`FENCE; TLBI.ALL`. A/D обеих PTE сохраняются. При unmap или уничтожении
каталога последняя X-трансляция удаляется из TLB до восстановления RW окна;
после смены прав окна TLB снова инвалидируется. Остальные X-алиасы удерживают R.
Окно возвращается в RW до повторной выдачи и обнуления свободного кадра.

Чтобы изменить загруженный код через физическое окно, доверенный загрузчик
обязан снять X со всех его алиасов через MMU API, включая другие каталоги,
и закончить запись до повторной выдачи X. Прямое изменение PTE или
`pageAccessReferences`, отключение MMU и дополнительные RW-окна обходят
контракт и не являются допустимым способом записи в защищённый код.
Окно предназначено для доверенного ядра, а не для доступа пользовательских
задач к физическим адресам. MMIO/VRAM остаются supervisor RW без U/X;
текущий API не выдаёт устройствам U даже через другой виртуальный адрес.
Будущая выдача MMIO/VRAM выбранному сервису требует отдельной явной проверки
его прав; X у устройств запрещён и после такой выдачи.

`mmuSplitSuperpage(directory, owner, virtual)` разделяет унаследованную
superpage устройств 4 МиБ на частную таблицу 4 КиБ, сохраняя все физические адреса,
разрешения и A/D. Общая таблица ядра не изменяется; операции пользовательских
отображений по-прежнему не могут менять supervisor-область.
RAM уже отображена общими таблицами: разделить её на независимые копии
физического окна нельзя, чтобы не сохранить устаревший writable-алиас кода.

После изменения отображений выполняются `FENCE; TLBI.ALL` с выключенным IE.
Полная инвалидация охватывает неактивные ASID, разрешения, global-записи и
все части superpage. `mmuSwitchAddressSpace(directory, owner, asid)` принимает
ASID 0…255 и выполняет `FENCE; TLBI.ALL; MTCR PTBR` до возврата прежнего STATUS.
Поэтому повторное использование ASID безопасно без отдельного реестра аренды;
кеширование между переключениями пока не используется.
`mmuActivateKernel()` тем же порядком возвращает начальный каталог и ASID 0.
Вход/выход в задачу должен переключать PTBR только через эти функции;
непосредственная запись PTBR с другим ASID сохраняет старые записи по ISA.

`mmuDestroyAddressSpace(directory, owner)` принимает только неактивный каталог.
До изменения проверяет владение частными таблицами и пользовательскими
страницами, затем делает частные записи каталога невалидными и выполняет
FENCE/TLBI до возврата памяти. Общие таблицы ядра не освобождаются.
Частные таблицы и каталог возвращаются распределителю; пользовательская
страница возвращается только после последней ссылки, включая алиасы и
несколько пространств одного владельца. Между разными владельцами совместное
использование пока запрещено. Неотображённые выделения остаются у владельца.
Таблицы изменяет только доверенное ядро; прямое изменение PTE/счётчиков
в обход API нарушает контракт. Защита изменений рассчитана на один CPU.

- [x] Новая пользовательская страница не содержит данные прежнего владельца
  (по исходникам).
- [x] Повторный map, неверные флаги и запрещённый U-алиас не изменяют таблицы.
- [x] Map/unmap/remap меняет доступ CPU после нужной инвалидации TLB.
  CPU читает и записывает новый кадр после remap; старый кадр не меняется.
  Проверены сохранение/пересоздание таблицы, оба пути unmap (CAUSE=9),
  RW→R (store fault, CAUSE=10) и RO→RW (успешная запись).
- [x] Переиспользование ASID не открывает старые отображения другой задачи.
  Отображения двух владельцев созданы до прогрева TLB. При переключении
  ASID 7→0→7 CPU читает новый кадр по общему VA и получает CAUSE=9
  по адресу, принадлежавшему только прежнему владельцу.
- [x] Запись в код/константы и исполнение из данных дают соответствующие faults.
  `.text` и `.rodata`: CAUSE=10; NX RAM: CAUSE=8. В user mode проверены
  запись в RX-код (CAUSE=10) и fetch из RW-данных (CAUSE=8).
  Supervisor-окно RX-кадра даёт store fault; после снятия X запись разрешена.
- [x] Ошибка создания каталога и его уничтожение не теряют страницы.
- [x] Проверить минимальную/максимальную RAM и неполную последнюю
  4 МиБ-область; таблицы не отображают память за концом RAM.
- [x] Guard и защищённые секции недоступны через другой виртуальный адрес.

Пункты закрыты запуском `tests/probe_mmu_cpu.py` на готовом образе
`laix/build/laix.img`; отдельные образы `mmu_remap.m`, `mmu_unmap.m`,
`mmu_protect.m`, `asid_reuse.m`, `text_write.m`, `rodata_write.m` и
`data_exec.m` ещё не собирались и не запускались. Monitor меняет данные
и сохранённые IRET-контексты временной машины; таблицы меняет CPU через
MMU API. User faults проверены через настоящий IRET; загрузчик задач и
планировщик относятся к следующим этапам. `tests/run_ready.py` принимает готовые
образы/карты, сверяет маркеры, код выхода и точные CAUSE/BADADDR/EPC;
для MMU-faults также проверяет активный ASID 7. `tests/test_ready_runner.py`
проверяет эти утверждения по UART fixtures и проверяет M/ASM без генерации кода.

## Когда этап готов

Есть распределитель, управляемые отображения с проверкой владения и
разрешений, возврат памяти при ошибках и повторяемые тесты доступов на CPU.
Одного включения MMU для завершения этапа недостаточно.

Проверки — анализ исходников и запуск готовых подходящих образов.
Сборка в текущей сессии не используется как проверка.
Контракт — [MMU в ISA](../../docs/INSTRUCTIONS.md#memory-management).
