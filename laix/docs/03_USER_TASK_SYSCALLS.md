# Этап 3. Пользовательская задача и системные вызовы

[План ядра](KERNEL.md) · [Предыдущий этап](02_MEMORY_MMU.md) · [Следующий этап](04_SCHEDULER_IRQ.md)

Статус: предстоит. Пролог уже выбирает доверенный стек при STATUS.PUM,
но настоящий запуск задачи в user mode на CPU ещё не подтверждён.
Цель — одна изолированная задача, безопасный переход через SYSCALL и
возврат с сохранением её контекста.

Зависимости: распределитель и операции MMU из этапа 2. ELF-загрузчик
пока можно заменить кодом, включённым в образ с явно заданными границами
и адресом исполнения.

## Что сделать

### Подготовить задачу

- [ ] Ввести минимальный Task/TCB: идентификатор, каталог страниц,
  user- и kernel-стек, сохранённый контекст и состояние.
- [ ] Выделить отдельные страницы кода, данных и user-стека; не открывать
  U-доступ к странице, содержащей также данные ядра.
- [ ] Создать RXU-код и RWU-данные/стек без X; оставить user-нулевую
  страницу и guard под стеком недоступными.
- [ ] Сохранить общие supervisor-отображения обработчика, низких слов
  входа, таблиц и kernel-стека без U.
- [ ] Создать kernel-стек задачи с guard/canary; установить KERNEL_SP,
  KERNEL_STACK_BOTTOM и KERNEL_STACK_TOP для выбранной задачи.
- [ ] Подготовить начальный TrapFrame: EPC entry, user-sp, определённые
  GPR, tp/TLS по необходимости, FCSR и корректные STATUS.PUM/PIE/PSS.
- [ ] Активировать каталог с TLB-протоколом и войти через IRET;
  до готовности IRQ-ветки оставлять PIE=0.
- [ ] Определить контракт user entry: собственная маленькая точка входа
  либо argc/argv/envp/auxv по ABI. Не использовать boot runtime M как user crt0.

### Определить syscall ABI

Предлагаемый первый набор; номера нужно закрепить перед реализацией:

| Вызов | Назначение |
| --- | --- |
| `debugPutChar(code)` | символ без чтения пользовательского указателя |
| `exit(code)` | завершить задачу и перейти в доверенный контекст ядра |
| неизвестный номер | вернуть -ENOSYS |

- [ ] Записать номера, аргументы, результаты и ошибки в ABI LA/IX.
- [ ] Читать номер из сохранённого r9, аргументы из r1–r6, результат
  записывать в r1; соблюдать сохранение остальных регистров по ABI.
- [ ] Продвигать EPC ровно на одну инструкцию для обработанного SYSCALL;
  ветки диспетчера завершать без fallthrough.
- [ ] Сделать user-обёртки на M через встроенный `syscall()`.
- [ ] Подготовить доверенный kernel-контекст для exit/фатальной ошибки
  единственной задачи; не возвращаться в завершённый user-код.

`debugPutChar` — временный инструмент. Консольный сервис появится на
этапе 6; форматирование строк не нужно в первом syscall.

### Пользовательские указатели и ошибки

- [ ] Сначала использовать syscall без указателей. Перед добавлением
  буферов реализовать проверку полного диапазона с защитой от переполнения.
- [ ] Проверять U и нужные права каждой страницы; supervisor-доступ
  к адресу сам по себе не доказывает допустимость пользовательского буфера.
- [ ] Создать copyFromUser/copyToUser, возвращающие ошибку вместо
  падения ядра; учитывать пересечение границ страниц.
- [ ] Зафиксировать политику: user fault завершает задачу и возвращает
  управление ядру, supervisor fault вызывает panic с дампом.
- [ ] Не читать user-память внутри EXL=1-пути без доказанного отображения.
  Для recoverable fault нужен отдельный протокол сохранения контекста
  и переработка TRAP_SAVED_R1 при вложенности.
- [ ] Освобождать память задачи после ухода с её kernel-стека и деактивации каталога.

## Что проверить

- [x] Интерпретация исходного пролога проверяет выбор kernel-стека
  и отсутствие обращений к памяти через недоверенный user-sp.
- [ ] На CPU задача действительно работает с UM=1 и выполняет свой код.
- [ ] SYSCALL приходит с PUM=1 на kernel-стек; IRET возвращает UM=1.
- [ ] При user-sp=0, невыровненном и недоступном sp вход в ядро
  не использует их как память.
- [ ] После многократных syscall сохраняются GPR, tp, sp, ra и FCSR;
  меняются только разрешённые ABI результаты.
- [ ] Неизвестный номер возвращает -ENOSYS без panic и повторения инструкции.
- [ ] Чтение/запись памяти ядра и исполнение NX-данных дают user fault.
- [ ] Привилегированная инструкция в UM не выполняется и не повреждает ядро.
- [ ] Exit прекращает задачу и переводит CPU в доверенное состояние.
- [ ] Буфер на границе страницы, адрес 0, supervisor-страница и
  переполнение address+length возвращают ошибку без double fault.
- [ ] Supervisor-тесты этапа 1 продолжают проходить с новым user entry.

## Когда этап готов

Реальная user-задача выводит символы через syscall, возвращается в UM
с сохранённым контекстом и штатно завершает работу. Запрещённый доступ
не выполняется и не повреждает ядро.
Контракт — [syscall и старт процесса в ABI](../../docs/ABI.md).
