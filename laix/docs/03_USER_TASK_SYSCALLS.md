# Этап 3. Пользовательская задача и системные вызовы

[План ядра](KERNEL.md) · [Предыдущий этап](02_MEMORY_MMU.md) · [Следующий этап](04_SCHEDULER_IRQ.md)

Статус: подготовка одной задачи, вход через IRET, user syscall/exit и
завершение по user fault подтверждены на CPU эмулятора:
[11 сценариев приёмки](../tests/USER_ACCEPTANCE.md).
Функции копирования user-буферов подтверждены
[9 CPU-сценариями при EXL=1](../tests/USER_BUFFERS_ACCEPTANCE.md).
Цель — одна изолированная задача, безопасный переход через SYSCALL и
возврат с сохранением её контекста.

Зависимости: распределитель и операции MMU из этапа 2. ELF-загрузчик
пока можно заменить кодом, включённым в образ с явно заданными границами
и адресом исполнения.

### Реализация и контракт первого входа

`src/task/task.m` содержит один `Task` — `firstTask`, ID 1, состояния
`EMPTY → READY → RUNNING → EXITED/FAULTED`. TCB хранит каталог, виртуальные границы user-стека,
адреса кода/данных, границы kernel-стека и сохранённый `TrapFrame`.
Первые user traps сохраняют контекст в TCB перед диспетчеризацией; действующий
кадр обработчика остаётся на kernel-стеке. Подготовка не активирует каталог.
При любой ошибке выделения или отображения она уничтожает неактивный каталог,
возвращает оставшиеся кадры и допускает повторную попытку.

| Диапазон VA | Назначение | Права |
| --- | --- | --- |
| `0x00000000…0x00000FFF` | NULL | не отображён |
| `0x40000000…0x40000FFF` | отдельная копия user-кода | RXU |
| `0x40001000…0x40001FFF` | обнулённые user-данные | RWU, NX |
| `0xBFFFE000…0xBFFFEFFF` | guard под user-стеком | не отображён |
| `0xBFFFF000…0xBFFFFFFF` | обнулённый user-стек | RWU, NX |

Все три user-кадра выдаются распределителем отдельно от образа ядра.
Загрузчик копирует только `[userCodeStart, userCodeEnd)` из `src/task/task.asm`
до назначения X; исходная страница ядра не получает U. После назначения X
общий supervisor-алиас кадра кода становится R без W/X/U. Каталог наследует
общие отображения RAM, таблиц, обработчика, boot-стека, UART и слов входа.

Для единственной задачи `start.asm` резервирует отдельные 8 КиБ kernel-стека
в BSS с выровненной guard-страницей перед ним; MMU оставляет обе kernel guard
страницы недоступными во всех каталогах. Стек обнуляется, в нижнем слове
устанавливается canary. До первого IRET `taskStart()` переключает PTBR
через `FENCE → TLBI.ALL → MTCR PTBR` (ASID 0), устанавливает три низких
слова стека и передаёт TCB-кадр в `trapRestoreFrame()`. Этот вход использует
тот же restore, что и `trapEntry`, с восстановлением sp последним.

Приватный entry-контракт: EPC=`0x40000000`, sp=`0xC0000000` (alignment 8),
r1=`0x40001000`, r2=4096; остальные GPR, включая tp/r28, fp/r29 и ra, равны 0.
TLS и argc/argv/envp/auxv отсутствуют. FCSR=0, сохранённый STATUS=`EXL|PUM`;
PIE/PSS/IE/UM/SS равны 0. IRET устанавливает UM=1, IE=SS=EXL=0.
Entry не возвращается: проверяет свой стек записью/чтением, записывает 1
в первое слово user-данных, выводит `U` и перевод строки через syscall 0,
затем выполняет `exit(0)` через syscall 1. Прямого доступа к устройствам нет.
User-blob автономен: все переходы локальные, константы входят в инструкции;
kernel continuation расположен за пределами копируемого диапазона.

`main.m` выполняет boot self-tests и инициализацию консоли, затем подготавливает
и запускает эту задачу. User syscall обрабатывается только для RUNNING-задачи
с соответствующим PTBR; остальные user exceptions завершают её как FAULTED.
Supervisor traps сохраняют политику self-test/panic первого этапа.

`tests/test_task.py` интерпретирует проверенный M AST и реальный assembly
restore: права и алиасы, обе guard-страницы, начальные GPR/FCSR/STATUS,
слова входа и порядок TLB/PTBR, kernel-стек user trap, сохранение TCB,
ошибки каждого отображения и все стадии нехватки памяти с откатом.
Байты blob и адреса линкера являются fixture; эти проверки не доказывают
выполнение нового образа на CPU. Сборка не запускалась.

### Определить syscall ABI

Номера закреплены в [ABI LA/IX](../../docs/ABI.md#laix-system-calls):

| Номер | Вызов | Результат и ошибки |
| --- | --- | --- |
| 0 | `debugPutChar(code)` | r1: 0; для code вне 0…255: -EINVAL (-22), без записи в UART |
| 1 | `exit(code)` | r1: полный Word-код завершения; возврата нет |
| прочие | неизвестный номер | r1: -ENOSYS (-38) |

- [x] Записать номера, аргументы, результаты и ошибки в ABI LA/IX.
- [x] Читать номер из сохранённого r9, аргументы из r1–r6, результат
  записывать в r1; соблюдать сохранение остальных регистров по ABI.
- [x] Продвигать EPC ровно на одну инструкцию для обработанного SYSCALL;
  ветки диспетчера завершать без fallthrough.
- [x] Сделать user-обёртки на M через встроенный `syscall()`.
- [x] Подготовить доверенный kernel-контекст для exit/фатальной ошибки
  единственной задачи; не возвращаться в завершённый user-код.

`debugPutChar` — временный инструмент. Консольный сервис появится на
этапе 6; форматирование строк не нужно в первом syscall.

`src/trap/trap.m:userSyscall()` читает сохранённый r9 и r1; r2–r6 пока не нужны
и игнорируются. Все returning-вызовы изменяют только r1 и EPC += 4;
r2–r31 и FCSR восстанавливаются полностью. Каждая ветка заканчивается return.
M-обёртки `user/syscalls.m` вызывают builtin `syscall()` и не импортируют
kernel-функции. У `exit` есть бесконечный user-цикл на случай ошибочного возврата.
Обёртки предназначены для будущих M user-программ; текущий blob написан на asm.

До первого входа `taskStart()` создаёт отдельный `kernelContext`: нулевые
GPR/FCSR, sp=`kernelStackTop`, EPC=`taskKernelResume`, STATUS=EXL без PUM/PIE/PSS,
сохранённый kernel PTBR. При exit `taskFinish()` сохраняет user-контекст с EPC+4;
при fault оставляет исходный EPC. TCB получает EXITED/FAULTED и код завершения.
Затем активируется kernel-каталог через FENCE/TLBI.ALL/PTBR, восстанавливаются
низкие слова boot-стека, а живой кадр заменяется доверенным `kernelContext`.
Общий restore читает кадр с ещё отображённого kernel-стека задачи; IRET
переводит CPU в supervisor mode на пустой boot-стек с IE/SS=0.
`taskKernelResume` вызывает `taskReap()` и остаётся в HLT-цикле.
Освобождение user-кадров и каталога происходит только в `taskReap()`.
Терминальный TCB сохраняется для диагностики и повторно не запускается.

`tests/test_task.py` проверяет реальные M-ветки и assembly save/restore:
повторные syscall с допустимыми/ошибочными аргументами, сохранение всех GPR/FCSR,
EPC+4, sp=0/невыровненный/недоступный, exit и все синхронные user faults,
независимый kernel-контекст, смену каталога и отложенное освобождение.
`tests/test_user_syscalls.py` проверяет передачу номера, аргумента и результата
через M builtin. Это исходниковые проверки с fixture аппаратных переходов,
не исполнение образа на CPU. Отдельное CPU-подтверждение готового образа
и границы проверки описаны в [приёмке](../tests/USER_ACCEPTANCE.md).

### Пользовательские указатели и ошибки

- [x] Сначала использовать syscall без указателей. Перед добавлением
  буферов реализовать проверку полного диапазона с защитой от переполнения.
- [x] Проверять U и нужные права каждой страницы; supervisor-доступ
  к адресу сам по себе не доказывает допустимость пользовательского буфера.
- [x] Создать copyFromUser/copyToUser, возвращающие ошибку вместо
  падения ядра; учитывать пересечение границ страниц.
- [x] Зафиксировать политику: user fault завершает задачу и возвращает
  управление ядру, supervisor fault вызывает panic с дампом.
- [x] Не читать user-память внутри EXL=1-пути без доказанного отображения.
  Для recoverable fault нужен отдельный протокол сохранения контекста
  и переработка TRAP_SAVED_R1 при вложенности.
- [x] Освобождать память задачи после ухода с её kernel-стека и деактивации каталога
  (проверено по исходникам и на CPU готового образа).

Отметки подтверждены проверками исходников без сборки. Syscall 0/1 остаются
без указателей; буферный syscall пока не добавлен. `src/mm/mmu.m` предоставляет:

- `mmuUserByteRangeValid(address, size)` — проверку произвольного байтового
  диапазона через `size <= USER_VA_END - address`, без переполнения.
- `mmuUserBufferValid(directory, owner, address, size, access)` — проверку
  всех страниц для `PTE_R`, `PTE_W` или их сочетания. Она не закрепляет
  отображения для последующего доступа после возврата.
- `copyFromUser(directory, owner, destination, source, size)` и
  `copyToUser(directory, owner, destination, source, size)` — копирование
  из user-адреса в kernel-буфер и обратно. User-адрес передаётся как `UWord`,
  kernel-буфер — как `*mut UByte` для назначения или `*UByte` для источника.
  Результат: 0 либо `-EFAULT` (-14).

Копирование удерживает `memoryLock` от проверки всего диапазона до последнего
байта: на одном CPU без планирования это сохраняет таблицы, права и время
жизни кадров. Каждая страница должна иметь V/U/R и требуемое право; каталог,
таблица и кадр проверяются по владельцу и ссылкам. Чтение допускает RO/RXU,
запись требует W; отсутствующие страницы, supervisor-отображения, superpage
и чужие кадры отвергаются. Также проверяется физический supervisor-алиас
кадра и его право R/W. Копирование обращается только к этим алиасам, делит
диапазон по границам страниц и допускает невыровненные адреса и несмежные
физические кадры. При недопустимом user-буфере назначения не изменяются.
Нулевая длина при допустимом каталоге даёт 0 без обращения к обоим буферам,
независимо от адресов. Ненулевой диапазон может заканчиваться ровно на
`USER_VA_END`, но не пересекать его.

Kernel-буфер должен быть доверенным, доступным на весь размер и не пересекать
user-кадры или метаданные MMU. Ошибка kernel-указателя остаётся ошибкой ядра.
Это протокол доказанного отображения для EXL=1; recoverable fault и вложенные
traps не реализованы. Для них по-прежнему нужен отдельный протокол контекста
и переработка единственного `TRAP_SAVED_R1`. При добавлении планирования/SMP
нужно заменить текущую блокировку протоколом закрепления отображений/кадров.

`tests/test_user_memory.py` исполняет проверенный M AST с байтовой RAM-fixture:
границы страниц и каталога, несмежные кадры, RO/RXU, U/R/W каждой страницы,
ошибку поздней/промежуточной страницы без частичной записи, NULL/supervisor/MMIO,
переполнение, неверного владельца/каталог/таблицу/кадр, нулевую длину и последний
user-байт. Каждый доступ к данным проверяется по действующему supervisor-алиасу
при выключенных IRQ; STATUS, включая EXL, и PTBR сохраняются. Эти проверки
сами по себе не подтверждают исполнение кода на CPU или отсутствие
аппаратного double fault. Отдельная
[CPU-приёмка](../tests/USER_BUFFERS_ACCEPTANCE.md) проверила настоящие функции
копирования при EXL=1: границы страниц, отсутствие U/W на поздней странице,
NULL, supervisor-адрес и переполнение. Недопустимые буферы возвращают
-EFAULT без частичной записи; эмулятор штатно завершает работу, exit 0.

CPU-отметки относятся к образу с SHA-256 из
[USER_ACCEPTANCE.md](../tests/USER_ACCEPTANCE.md) и
[USER_BUFFERS_ACCEPTANCE.md](../tests/USER_BUFFERS_ACCEPTANCE.md).
В `natural` исполняются исходный main и user-blob; остальные случаи используют
сохранённые контексты и копии существующих инструкций. Обычные отображения
меняет kernel API; CPU-проба буферов также использует явно описанную
отрицательную fixture со снятием U и настоящей инвалидацией TLB.

## Когда этап готов

Реальная user-задача выводит символы через syscall, возвращается в UM
с сохранённым контекстом и штатно завершает работу. Запрещённый доступ
не выполняется и не повреждает ядро.
Контракт — [syscall и старт процесса в ABI](../../docs/ABI.md).
