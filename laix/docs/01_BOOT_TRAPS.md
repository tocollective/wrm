## Что есть сейчас

- Прошивка загружает boot-образ в физическую память с `0x00010000`.
- `laix/build.sh` компонует отдельные объекты с собственным `start.asm`
  первым; стандартные `crt0.asm` и `trap.asm` не подключаются.
- Старт сохраняет boot info, проверяет RAM, обнуляет BSS, устанавливает
  стек 8 КиБ и `trapEntry`, вызывает `main(0, null)`.
- `trap.asm` сохраняет кадр на 160 байт и вызывает `trapDispatch` на M.
  Вход из user mode переключается на доверенный стек текущего контекста
  через низкое слово `KERNEL_SP`; supervisor mode сохраняет текущий стек.
  Ожидаемый self-test `BREAK` или `SYSCALL` — взведённый `trapExpect` и
  пришедший из supervisor — возвращается после инструкции, `SYSCALL` с
  `-ENOSYS`. Любой другой `BREAK`/`SYSCALL` и остальные исключения выводят
  полный дамп через UART и выключают машину с кодом 254.
- До экранной демонстрации предусмотрены прямой `breakpoint()`, самопроверки
  контекста через `BREAK` и неизвестный syscall, контроль `IE` и PIC `ENABLE`.
- `memory.m` резервирует всю память до округлённого вверх `__bss_end`;
  `physicalPageAvailable()` задаёт допустимые целые страницы RAM для
  будущего распределителя, но не учитывает последующие выделения.
- `mmu.m` включает supervisor identity map RAM, VRAM и MMIO до
  самопроверок; guard page под стеком не имеет действительного PTE.
  `mmuInitAddressSpace()` переносит эти отображения без `U` в новый каталог.
- LA/IX имеет экранную консоль, загрузку растров шрифта с диска и RNG.
  Текущий `main` инициализирует консоль, печатает `LA/IX` и выполняет HLT.

В этой версии обработчик сохраняет `EXL = 1` до `IRET`. Это простой
контракт: весь код обработчика и используемая им память должны быть
доступны и не должны вызывать исключений. Ошибка внутри такого обработчика
останавливает CPU как double fault; повторного входа в `panic` не будет.

### 1.3. Реализовать старт ядра

Состояние при передаче управления прошивкой:

| Значение | Состояние |
| --- | --- |
| `r1` | адрес boot info, сейчас `0x00001000` |
| `sp` | `0x00010000`, пустой стек, выравнивание 8 |
| `STATUS` | `0x10`: supervisor, `IE = 0`, `EXL = 1` |
| `IVEC`, `PTBR` | 0: своего обработчика нет, MMU выключена |
| `.bss` | не обнулена |

Последовательность старта:

1. Сохранить исходный `r1` в регистре, который не используется циклом
   обнуления BSS. Запись в глобальную переменную до обнуления BSS
   будет потеряна.
2. Установить адрес минимального раннего обработчика в `IVEC`. Его задача —
   остановить машину с коротким сообщением без обращения к BSS и без стека.
   Затем очистить `EXL`, сохранив `IE = 0` и supervisor mode. Ошибки старта
   без trap (boot info, RAM, возврат `main`) идут в `earlyPanic` и не печатают
   `CAUSE/EPC/BADADDR`: там остались значения reset или прошивки. Исключение
   до установки `trapEntry` идёт в `earlyTrapPanic`, который их печатает.
3. До записи в BSS проверить на ассемблере минимальный контракт boot info:
   magic, наличие поля размера RAM и достаточность RAM до `__bss_end`,
   включая выделенный стек. Затем обнулить диапазон
   `__bss_start`–`__bss_end` без вызовов функций и без использования
   будущего стека в BSS.
4. Сохранить адрес boot info в глобальном состоянии. Полный разбор
   оставшихся полей блока можно выполнить на M после установки стека
   и полноценного обработчика.
5. Переключить `sp` на верх выделенного стека ядра с выравниванием 8.
   Записать его и границы стека в низкую область входа; обнулить её временное
   слово. Начальный стек прошивки нужен только на время старта.
6. Установить полный `trapEntry` в `IVEC` до выполнения кода M, который
   может вызвать исключение. `IE` оставить выключенным.
7. Инициализировать `FCSR` и вызвать точку входа ядра по ABI M.
   Boot info передавать по явно определённому контракту; не считать,
   что стандартные `argc` и `argv` содержат его.
8. Если точка входа неожиданно возвращается, перейти в явный путь
   остановки с диагностикой.

- [x] Разместить стек как выделенную область BSS с известными границами;
  начальный размер, например 8 КиБ, считать предварительным.
- [x] Исключить стек из будущего распределителя страниц.
- [x] Добавить контрольное значение у нижней границы стека. Оно обнаружит
  часть переполнений при последующей проверке, но не предотвратит их.
- [x] После появления MMU добавить недоступную guard page под стеком.
- [x] Не использовать фиксированную вершину стека, не проверив размер RAM
  и пересечение с образом и служебной памятью.

`start.asm` выделяет `kernelStackGuard` на 4096 байт, затем
`kernelStackBottom`–`kernelStackTop` на 8192 байта; все границы кратны
4096. Canary остаётся в первом слове доступного стека. `kernelInit()`
проверяет границы и запускает `memoryInit()` перед `mmuInit()`.

Будущий распределитель должен формировать список свободных страниц
только через `physicalPageAvailable(address)`. Функция отвергает
невыровненные адреса, неполную последнюю страницу RAM и всю область
`[0, alignUp(__bss_end, 4096))`. Так сохраняются boot info, образ ядра,
стек, guard page, остальные глобальные данные и начальные таблицы страниц.
Само выделение и освобождение страниц пока не реализовано.

Начальная MMU использует каталог и две таблицы по 4 КиБ в BSS.
Первые 4 МиБ, где лежат ядро, BSS и guard, и неполный последний регион
отображаются страницами 4 КиБ, остальные регионы RAM — суперстраницами
RW без X. Если регионы совпадают, используется одна таблица. Права
следуют W^X: `.text` — RX, `.rodata` — R, данные, стеки и свободная RAM —
RW. PTE страницы 0, бывшего стека firmware и guard page равны нулю, других
отображений их физических адресов нет. VRAM и MMIO — RW; user mode
запрещён, ROM не отображается.
После заполнения таблиц выполняются `FENCE`, `TLBI.ALL` и установка
`PTBR`. Код обработки исключений, его данные, доступная часть стека
и UART остаются отображёнными. При слишком низком `sp`, в том числе при
переполнении стека до guard page, вход в обработчик переходит к аварийному
пути `.bad_stack` (см. шаг 2 разбора входа).

`tests/test_memory.py` проверяет алгоритмы исходного M без сборки.
`tests/programs/mm/stack_guard.m` подготовлен для проверки store page fault при
записи в guard page с исправным стеком; ожидает `CAUSE=10` и выход 254.
`mmuInitAddressSpace(directory)` инициализирует принадлежащую вызывающему
неактивную страницу каталога из допустимой свободной RAM. Он копирует
эталонный каталог, сохраняя без `U` код входа и обработчика, первые 8 КиБ,
стек, данные ядра, таблицы страниц и устройства аварийного вывода. Адрес
активного каталога, зарезервированная память, невыровненный адрес и адрес
за RAM отвергаются без записи. Общие таблицы и ненулевые записи каталога
нельзя изменять при добавлении пользовательских отображений: для них
предназначены свободные записи каталога. Guard page и зарезервированные
страницы ядра нельзя отображать пользовательскими алиасами. Перед переключением
`PTBR` вызывающий код выполняет `FENCE` и инвалидирует TLB. Таблицы ядра
сохраняют тождественное W^X-отображение RAM без `U`.
Выделение страниц, отображение пользовательского кода и переключение
`PTBR` планировщиком ещё не реализованы.

### 1.4. Зафиксировать формат TrapFrame

Предлагаемый формат на M:

```m
type TrapFrame {
    regs:     UWord[32],
    epc:      UWord,
    status:   UWord,
    cause:    UWord,
    badaddr:  UWord,
    fcsr:     UWord,
    ptbr:     UWord,
    reserved: UWord[2],
}
```

`regs[n]` хранит значение `rn` прерванного кода. `regs[0]` записывается
как 0, `regs[30]` содержит исходный `sp`, а не адрес кадра обработчика.
`regs[28]` — исходный `tp`, `regs[29]` — `fp`, `regs[31]` — `ra`.

| Поле | Смещение, байт |
| --- | ---: |
| `regs[0]` | 0 |
| `regs[1]` | 4 |
| `regs[28]` | 112 |
| `regs[29]` | 116 |
| `regs[30]` | 120 |
| `regs[31]` | 124 |
| `epc` | 128 |
| `status` | 132 |
| `cause` | 136 |
| `badaddr` | 140 |
| `fcsr` | 144 |
| `ptbr` | 148 |
| `reserved` | 152 |

Размер — 160 байт. Естественное выравнивание структуры — 4 байта,
но её размещение на 8-выровненном стеке и размер, кратный 8,
сохраняют выравнивание перед вызовом M.

`status` — снимок после аппаратного входа в обработчик, а не исходное
значение до исключения. Предыдущий режим сохранён в `PUM`, разрешение
прерываний — в `PIE`, single-step — в `PSS`.

- [x] Объявить соответствующие смещения и размер для ассемблера.
- [x] Проверять соответствие через `sizeof(TrapFrame)` и
  `offsetof(TrapFrame, поле)`; изменение структуры должно сопровождаться
  изменением ассемблерных констант.
- [x] Инициализировать резервные слова нулями.
- [x] Считать `ptbr` снимком для диагностики на первом этапе. Изменение
  адресного пространства позже станет отдельным протоколом планировщика.
- [x] Закрепить `SCRATCH` за временной работой входа/выхода; не использовать
  его одновременно как долговременное состояние другого компонента.

### 1.5. Сохранить контекст до вызова M

Аппаратный вход меняет управляющие регистры и переводит CPU в supervisor
mode. Он не сохраняет GPR и не меняет `sp`.

Вход из обоих режимов:

1. Записать исходный `sp` в `SCRATCH`, проверить `PUM` до доступа к памяти.
   При входе из user mode загрузить `sp` через `KERNEL_SP(r0)`; при входе
   из supervisor mode восстановить текущий `sp` из `SCRATCH`.
2. Сохранить `r1` через `TRAP_SAVED_R1(r0)`. Проверить выбранный доверенный
   `sp`: выравнивание 8, границы текущего стека и запас 512 байт под обработчик
   сверх кадра и canary. При ошибке перейти в `.bad_stack`, не обращаясь
   ни к отвергнутому, ни к прерванному стеку: скопировать весь контекст в
   статический `trapEmergencyFrame`, вывести без зависимостей раннюю строку
   с `CAUSE/EPC/BADADDR`, отвергнутым `sp`, прерванным `sp` (`scratch`),
   границами стека и `ra`, затем на статическом аварийном стеке 2 КиБ вызвать
   `trapBadStack()`, который печатает полный dump через обычный `panic`.
   Если M-код уже повреждён и dump не удастся, ранняя строка уже выведена.
   Иначе выделить кадр и скопировать в него исходный `r1`.
3. Прочитать исходный `sp` из `SCRATCH` и записать в `regs[30]`.
4. Сохранить все остальные изменяемые GPR, включая `ra`, `tp`, `fp`,
   аргументы и `r9`. Исключение может произойти в любой инструкции,
   поэтому правила callee-saved сами по себе недостаточны.
5. Сохранить `EPC`, `STATUS`, `CAUSE`, `BADADDR`, `FCSR` и `PTBR`.
6. Установить окружение ядра для `FCSR`. На первом этапе ядро не использует
   TLS; если оно появится, отдельно установить kernel `tp` после сохранения
   прерванного значения.
7. Передать указатель на кадр в `r1`, вызвать экспортированную функцию
   `trapDispatch(frame: *mut TrapFrame): Void`.

`TRAP_SAVED_R1` безопасен только при одноядерном невложенном входе с
`EXL = 1`. Поддержка вложенности потребует изменения этого пролога.
Проверка запаса дополняет guard page и контроль роста стека
внутри вызываемых функций.

Ассемблер не должен вызвать M, пока контекст не сохранён полностью:
обычный вызов перезапишет `ra`, а функция вправе менять caller-saved
регистры. `trapDispatch` изменяет сохранённый кадр, чтобы задать результат
обработки, адрес продолжения или возвращаемое значение.

Переключение стека при входе из user mode:

- [x] До доступа к стеку проверить `STATUS.PUM`.
- [x] При входе из user mode загрузить доверенный стек ядра текущей задачи;
  пользовательский `sp` сохранить в кадре, но не использовать для записи.
- [x] При входе из supervisor mode продолжить на текущем стеке ядра.
- [x] Обеспечить отображение кода входа, данных переключения стека и стека
  ядра в каждом адресном пространстве без права `U`.
- [x] Для схемы из ABI хранить `KERNEL_SP` в зарезервированном слове первых
  8 КиБ, доступном через `offset(r0)`. Не пересекать его с boot info и
  таблицей устройств. Обычная глобальная переменная после образа сама
  по себе этого размещения не обеспечивает.
- [x] Слова входа в конце страницы 1, страница 0 не отображена: NULL в ядре
  даёт page fault. Проверено на готовом `laix.img` без сборки через
  `tests/probe_null_page.py`: слова `0x1FF0–0x1FFC`, PTE[0]=0, страница 1
  supervisor RW, настоящий NULL call даёт CAUSE=8, EPC=BADADDR=0 и exit 254.
  Готового `null_call.img` нет; probe использует инструкцию вызова из ROM
  и проверки case `null_call` в `run_ready.py` с точным адресом возврата.

Низкая область входа резервируется LA/IX явно, вне образа и BSS:

| Адрес | Слово | Назначение |
| --- | --- | --- |
| `0x00001FF0` | `KERNEL_SP` | доверенный `sp` для входа из user mode |
| `0x00001FF4` | `KERNEL_STACK_BOTTOM` | нижняя граница стека, адрес canary |
| `0x00001FF8` | `KERNEL_STACK_TOP` | верхняя граница стека |
| `0x00001FFC` | `TRAP_SAVED_R1` | временное сохранение `r1` при входе |

Все четыре слова доступны через `offset(r0)` и лежат в конце страницы
boot info (`BOOT_INFO_LIMIT` = `0x1FF0`). `kernelInit()` требует, чтобы boot
info и таблица устройств заканчивались ниже этой границы. Страница 0 не
отображается ни в одном каталоге: NULL load, store и call дают page fault, а
не исполняют `HLT` (опкод `0x00`) с выходом 0. `start.asm` записывает слова
до установки полного `IVEC`; `memoryInit()` исключает низкие страницы из
распределения.
Загрузочный контекст использует стек BSS. Будущий планировщик обязан перед
запуском задачи установить canary её стека и согласованно обновить первые
три слова при выключенных IRQ, до возврата в user mode. Весь выбранный стек
и низкая область должны присутствовать в новом каталоге без `U`; каталоги
инициализируются через `mmuInitAddressSpace()`. Эти слова остаются неизменными
на протяжении невложенного обработчика. Вход не перезаписывает `KERNEL_SP`
прерванным пользовательским `sp`: последний хранится только в `SCRATCH`
и `regs[30]`, восстанавливается последней загрузкой перед `IRET`.

`tests/test_trap_entry.py` интерпретирует исходные инструкции входа и
ассемблерной самопроверки без сборки; M-диспетчер выполняется по проверенному
AST. Проверяются оба режима, смена текущего стека, недоступный/невыровненный
user `sp`, сохранение регистров и отказ до записи кадра при плохом стеке.
Аппаратные переходы моделируются на синтетических адресах инструкций;
эти тесты не проверяют кодировку инструкций, конвейер и MMU эмулятора.
`tests/test_memory.py` проверяет наследование отображений новыми каталогами.

### 1.6. Разбирать причину входа

| Причина | Первое поведение | Что делать с `EPC` |
| --- | --- | --- |
| `CAUSE = 13`, `BREAK` | ожидаемый self-test: возврат; иначе `panic` с кадром | прибавить 4 только ожидаемому |
| `CAUSE = 12`, `SYSCALL` | ожидаемый self-test: `-ENOSYS` в `regs[1]`; иначе `panic` (user syscall — этап 3) | прибавить 4 только ожидаемому |
| `CAUSE = 0`, IRQ | на этапе 1 неожиданное событие, `panic`; затем отдельная IRQ-ветка | не прибавлять 4 |
| ошибки инструкции, адреса, доступа | `panic` с кадром | не возвращаться |
| `CAUSE = 14`, single-step | пока `panic`; позднее отладчик | при продолжении не прибавлять 4 |
| `CAUSE = 15`, trigger | пока `panic`; позднее отладчик | зависит от события и действия отладчика |

Для будущего восстановления page fault после исправления отображения
нужно повторить инструкцию с прежним `EPC`. Безусловный `EPC += 4`
теряет инструкцию или пропускает ещё не выполненную работу.

В IRQ-ветке источник определяется через PIC `CLAIM`. Чтение `CLAIM`
не снимает запрос: нужно очистить причину в устройстве. У PIC WRM нет
отдельного регистра EOI. Не включать IRQ, пока эта обработка не готова.

### 1.7. Вернуться через IRET

1. После возврата из M сохранить режим supervisor, `IE = 0`, `EXL = 1`.
2. Восстановить `STATUS` из сохранённого снимка с этим контрактом, затем
   `EPC`; исходные `PIE`, `PUM`, `PSS` должны остаться корректными.
3. Восстановить `FCSR` и GPR, удерживая доступ к кадру до последней загрузки.
4. Восстановить исходный `sp` последним и выполнить `IRET`.

`IRET` делает `pc = EPC`, `IE = PIE`, `UM = PUM`, `SS = PSS`, `EXL = 0`.
Обычный `ret` возвращается через `ra` и не выполняет этот протокол.
Нельзя заранее включать user mode или IRQ записью в `STATUS`, пока
восстановление регистров ещё не закончено.

Не восстанавливать автоматически все управляющие регистры: `IVEC`
остаётся адресом входа ядра, `SCRATCH` — временным, `CAUSE`/`BADADDR` —
снимками причины. Запись `PTBR` нужна при управляемом переключении
адресного пространства, а не для каждого обычного возврата.

### 1.8. Сделать независимую диагностику

- [x] Реализовать UART-вывод через `*volatile mut` по `0xFD002000`:
  символ, строка ASCII, фиксированное восьмизначное hex-число.
  TX на WRM никогда не блокируется; ожидание IRQ не нужно.
- [x] Не использовать экранную консоль, диск, распределитель памяти,
  блокировки и IPC в обязательном пути `panic`.
- [x] Выводить сообщение, стадию инициализации, имя и номер причины,
  `EPC`, `BADADDR`, `STATUS`, `PTBR`, `FCSR` и все GPR.
- [x] Отмечать предыдущий режим по `PUM`; при IRQ пояснять, что `BADADDR`
  не обновлялся и не описывает текущую причину.
- [x] Не читать память по аварийному `sp`, `fp`, `EPC` или `BADADDR`
  без отдельной проверки. Первый вариант не разворачивает стек.
- [x] После сообщения оставить IRQ выключенными и выключить машину через
  power controller с кодом 254; запасной путь — `HLT` в цикле.
  Один headless `HLT` сам даёт код 0.
- [x] Хранить карту символов для сопоставления `EPC` с кодом.

Пример формата; числа и текст ниже иллюстративны:

```text
LA/IX PANIC: unexpected exception
stage=trap-selftest origin=supervisor
cause=00000003 (misaligned load)
epc=00012340 badaddr=00010001
status=00000010 ptbr=00000000 fcsr=00000000
r00=00000000 r01=... r02=... r03=...
...
r28=... r29=... r30=... r31=...
```

Ранний обработчик из `start.asm` должен быть ещё проще: только короткий
ASCII-текст и значения управляющих регистров, выводимые без вызовов и
стека. Реализован вывод причины, `CAUSE`, `EPC`, `BADADDR`. Он работает
до обнуления BSS и до установки полноценного входа.

Double fault при `EXL = 1` не передаётся программному обработчику.
Для него использовать дамп эмулятора, `--debug`, monitor и короткую трассу
готового образа. Отдельный аварийный стек можно добавить позже, но он
не заменяет корректный, не вызывающий исключений пролог.

### 1.9. Что проверить: критерии готовности

Runtime-критерии ниже подтверждены запуском образов `tests/programs/trap/trap.m`,
`tests/programs/trap/trap_fault.m` и `tests/programs/mm/stack_guard.m` на эмуляторе 2026-10-03.
Точки входа выбираются через `LAIX_MAIN`; самопроверка выполняется и при обычном
старте. `kernelInit()` проверяет прямой `breakpoint()`, два ассемблерных входа
с известными GPR и `FCSR`, результат встроенного `syscall()`, выключенные
`IE` и PIC `ENABLE` до и после входов. Ассемблерный syscall изменяет ожидаемое
значение только `r1` на `-ENOSYS`, проверяя также `r2`, номер вызова в `r9`,
`tp`, `ra` и `sp`. Для каждого входа нужен возврат к следующей инструкции.

Проверки исходников запускаются без генерации кода, ассемблирования и линковки:

```sh
python3 -B -m unittest discover -s laix/tests -p 'test_*.py'
```

| Критерий | Подтверждение по исходникам |
| --- | --- |
| Boot info и BSS | `test_boot.py`: порядок записей настоящего `start.asm` на грязной BSS; выполнение проверок `boot.m`, независимая копия boot info, отказ при неверных полях и диапазонах устройств |
| Стек и служебная память | `test_boot.py`: отказ при неверных границах; `test_memory.py`: резервирование стека, guard, образа и таблиц |
| Guard page | `test_memory.py`: PTE отсутствует и физическая страница не имеет алиаса; сам store page fault требует эмулятора |
| `TrapFrame` | `test_kernel.py`: тип M, размер, смещения, все GPR и управляющие регистры |
| `BREAK` и syscall | `test_trap_entry.py`: реальный M-диспетчер и ассемблерная самопроверка, результат `-ENOSYS`, сохранение GPR/FCSR, продвижение `EPC`; неожиданные, невзведённые, с другим cause и user `BREAK`/`SYSCALL` дают panic без продвижения `EPC`, ожидание одноразовое |
| Невыровненная загрузка | Подготовлен `trap_fault.m`; `test_trap_entry.py` проверяет перенос заданных `CAUSE`, `BADADDR`, `EPC` в аварийный кадр без изменения `EPC` |
| Аварийная диагностика | `test_kernel.py`: зависимости только от UART, статических данных и кадра; ранний путь не использует стек и печатает поля trap только после trap; `test_trap_entry.py`: `.bad_stack` сохраняет весь контекст в статический кадр, печатает `sp`, `scratch`, границы и `ra`, вызывает `trapBadStack` на аварийном стеке, не трогая ни одного стека |
| Запрет IRQ | `test_boot.py`: старт обнуляет `STATUS` и PIC `ENABLE`; проверки `boot.m` отвергают включённые IRQ до и после self-test |

- [x] Ядро сохраняет и проверяет boot info, BSS обнуляется до использования.
- [x] Стек ядра не пересекается с образом и служебными областями.
- [x] Запись в guard page после включения MMU даёт store page fault.
- [x] Размер и смещения `TrapFrame` совпадают в M и ассемблере
  (проверено type checker и статическим тестом).
- [x] `breakpoint()` входит в `trapDispatch` и продолжает исполнение ровно
  после `BREAK`.
- [x] Ассемблерный self-test с известными значениями GPR подтверждает их
  сохранение; проверить также `sp`, `tp`, `ra` и `FCSR`.
- [x] Неизвестный `SYSCALL` возвращает `-ENOSYS`, сохраняя остальные
  регистры согласно ABI; адрес продолжения не зацикливается на `SYSCALL`.
- [x] Намеренная невыровненная загрузка выдаёт ожидаемые `CAUSE`,
  `BADADDR`, `EPC` и останавливает ядро.
- [x] Диагностика работает без инициализации экрана и загрузки шрифта.
- [x] Переполнение стека ядра даёт раннюю строку с `sp` и полный dump.
  Аварийный путь проверен без сборки на готовом `laix.img` через
  `tests/probe_stack_overflow.py`: SP у нижней границы, настоящий store page
  fault в guard, статический TrapFrame и аварийный стек, все регистры
  сохранены, exit 254. Использованы проверки case `stack_overflow`.
  Отдельного образа `tests/programs/mm/stack_overflow.m` нет; его рекурсия не запускалась.
- [x] До готовности IRQ-ветки `IE = 0`, PIC `ENABLE = 0`.

`tests/probe_boot.py` дополняет запуск через локальный monitor эмулятора:
до `kernelStart` заполняет всю BSS значением `0xA5A5A5A5` и считывает её обратно;
перед первой инструкцией `main` проверяет каждое из 7323 слов. Ненулевыми
остаются только намеренно установленные canary и адрес boot info. После
`kernelInit` копия boot info совпадает с оригиналом и не меняется при записи
в исходный блок. До и после инициализации проверены границы `sp`, `IE = 0`
и PIC `ENABLE = 0`. Для четырёх входов monitor сверяет GPR и `FCSR` перед
прологом и после `IRET`, подтверждает `pc = EPC + 4`, результат syscall
`r1 = -ENOSYS`. Точные значения аварийных кадров и воспроизведение проверки
сохранены в [`tests/ACCEPTANCE.md`](../tests/ACCEPTANCE.md).

`tests/run_ready.py` запускает готовые образы с готовым ROM и эмулятором,
не вызывая компилятор, ассемблер или линкер. Каждый образ должен соответствовать
своей карте символов и тестовой точке входа. Пример для трёх готовых артефактов:

```sh
python3 -B laix/tests/run_ready.py \
    --case trap /путь/trap.img /путь/trap.map \
    --case trap_fault /путь/trap_fault.img /путь/trap_fault.map \
    --case stack_guard /путь/stack_guard.img /путь/stack_guard.map
```

Runner проверяет WRMB-заголовок и размещение стека по карте, запускает копию
только загрузочной части образа без растров шрифта, сверяет UART и код выхода.
Для аварийных тестов обязательны причина, `BADADDR`, точный `EPC` метки
аварийной инструкции, все 32 GPR, `FCSR`, включённая MMU, выключенный `IE`
и завершение с кодом 254. `HLT` с кодом 0, ранний panic, неверная причина
или неполный дамп не проходят. Карта старого образа без `kernelStackGuard`
отвергается до запуска; экранная демонстрация не заменяет `tests/programs/trap/trap.m`.

Runtime-критерии выше не считаются выполненными только по type checker,
статическому анализу, интерпретации исходников или тестам самого runner.
