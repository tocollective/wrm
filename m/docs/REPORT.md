# M: разбор примера и что нужно языку

Отчёт по [examples/example.m](../examples/example.m) на 2026-10-01
(вторая версия примера: без `entry` и без функции-поля в `Color`).
Сверялся с [docs/ABI.md](../../docs/ABI.md),
[docs/INSTRUCTIONS.md](../../docs/INSTRUCTIONS.md) и
[docs/SPECIFICATION.md](../../docs/SPECIFICATION.md).

> Все решения из этого отчёта собраны в спецификацию:
> [spec/README.md](spec/README.md). Отчёт остаётся историей: почему
> выбрано именно так и из каких вариантов.

Пункты разбиты по тому, **когда** их решать:

- **до** — от этого зависит синтаксис или ABI. Если отложить, придётся
  переписывать парсер или уже написанный на M код;
- **вместе** — нужно для первой рабочей версии компилятора;
- **потом** — можно добавить позже, ничего не сломав.

---

## 0. Коротко

Направление нормальное: C-подобный системный язык без рантайма, с
синтаксисом в духе Swift/Zig/Odin. `let`/`let mut`, типы после имени,
`if` без скобок, обязательные фигурные скобки, `extern` для внешних
символов, designated-инициализаторы. Это хорошо ложится на однопроходный
парсер и на ABI машины.

Вторая версия примера уже согласована сама с собой. `colorAdd` принимает
и возвращает `Color` по значению, `main` стала обычной функцией, которую
вызывает `crt0`. Остались:

- одна настоящая ошибка — `0...(argc - 1)` при `argc` = 0 (2.1);
- несколько правил, которые нужно записать, чтобы пример однозначно
  компилировался (2.2–2.10).

Самое важное из отсутствующего — то, без чего на этой машине не
написать ядро и драйверы: доступ к MMIO (4.1), специальные инструкции
(4.2), атомики, атрибуты секций и линковки. Подробно — в разделе 4.

## 1. Что в примере уже хорошо

- **`let` для функций и переменных.** Парсер различает их по токену после
  имени: `(` или `:`. Это LL(1), без неоднозначностей.
- **Типы после имени** (`x: T`). Объявления читаются слева направо, и
  нет «спирального» синтаксиса C.
- **`let` неизменяемый по умолчанию, `let mut` для изменяемых.**
- **`for i in a..b` с константным `i`.** Компилятор может держать `i` в
  регистре и не следить за записями в него.
- **`if`/`else if`/`else` без скобок вокруг условия.**
- **`extern` с явной сигнатурой.** Это прямой мост к C ABI и к функциям
  на ассемблере.
- **Designated-инициализаторы `.r = ...`.**
- **`Color` передаётся по значению.** 3 байта едут в одном регистре
  (`r1`), а результат возвращается в `r1` (ABI, «Arguments», «Return
  values»). Указатели тут не нужны, и `colorAdd` — чистая функция.
- **`main(argc, argv): Word`** совпадает с тем, что ожидает `crt0` по ABI
  («Process start»). `envp` можно не объявлять, как и в C.

## 2. Что осталось в примере — до

### 2.1 `0...(argc - 1)` при `argc` = 0 — закрыто, см. 2.9

```
for i: UWord in 0...(argc - 1) {      // строка 37
    puts(argv[i])
```

`argc` беззнаковый. При `argc` = 0 выражение `argc - 1` равно
`0xFFFFFFFF`, и цикл пройдёт 4 миллиарда раз, читая память за концом
`argv`. В Unix `argc` = 0 допустим (`execve` с пустым `argv`), а ядро
этой ОС тоже сможет так запустить программу.

Закрытый диапазон с `- 1` — классический источник этой ошибки.
**Рекомендация:** основным сделать полуоткрытый диапазон и записать
его в спецификации:

- `a..<b` — полуоткрытый, `a...b` — закрытый (как в Swift);
- или `a..b` — полуоткрытый, `a..=b` — закрытый (как в Rust).

Тогда цикл — `for i in 0..argc`, без вычитания и без особого случая.

### 2.2 `*UByte[]` — правило чтения типа — закрыто

**Решено:** три правила ниже, без срезов (`argv.len` не нужен):

1. `[]` относится ко всему типу слева: `*UByte[4]` — массив из 4
   указателей. Указатель на массив пишется со скобками:
   `*(UByte[640])`.
2. `T[]` в параметре — указатель на первый элемент, как в C: то же,
   что `*T`, только для чтения. `mut T[]` — то же, что `*mut T` (3.3).
   Длина передаётся отдельно (`argc`). Вне параметров `T[]` без размера
   не встречается.
3. `T[N]` — значение: копируется при присваивании и передаче.

`argv` теперь `*UByte[]`: строки беззнаковые (3.1).

Разбор, из которого выбирали:

Массив указателей — нормальный выбор, это `char *argv[]` из C. Разница
с «указателем на массив» важна не здесь, а в других местах, поэтому
правило всё равно нужно записать:

- **Как читать `*Byte[4]`.** Если `[]` применяется ко всему, что слева,
  то это массив из 4 указателей на `Byte`. Тогда указатель на массив
  (например, на строку кадрового буфера) пишется со скобками:
  `*(Byte[640])`. Скобки в типах парсер должен поддерживать.
- **Что такое `T[]` без размера.** В параметре это может быть:
  - просто указатель, как в C: 4 байта, один регистр, `argv[i]`
    без проверок, длина передаётся отдельно (`argc`);
  - срез: адрес и длина, 8 байт, пара регистров (ABI: структура до
    8 байт идёт в двух регистрах). Тогда `argc` не нужен, есть
    `argv.len` и можно проверять границы.

  Для `extern`-функций C подходит только первый вариант. Можно иметь
  оба, но под разными записями.
- **`T[N]` — значение или указатель.** В C массив в параметре
  превращается в указатель, а в структуре — нет. Если в M массив
  фиксированного размера всегда значение (копируется при передаче),
  правила проще. Но `T[64]` в параметре займёт 64 × `sizeof(T)` байт на
  стеке и вызовет `memcpy`.

Записать достаточно три строки: «`[]` относится ко всему типу слева»,
«`T[]` в параметре — указатель на первый элемент», «`T[N]` — значение».

### 2.3 Запятые в инициализаторе — закрыто

**Решено:** запятые между полями обязательны, последняя запятая
необязательна. То же правило — для полей в объявлении `type`:

```
type Color {
    r: UByte,
    g: UByte,
    b: UByte,
}
type Point { x: Word, y: Word }
```

Пример: [examples/init.m](../examples/init.m).

В `colorAdd` (строки 11–13) поля не разделены запятыми, а в
`colorGetRed` (строки 20–22) разделены. Нужно выбрать одно:

- запятые обязательны, последняя — по желанию (как в Rust/Zig/Swift);
- разделитель — запятая или перевод строки (как в Go с его
  автоматическими `;`). Это усложняет лексер, и тогда то же правило
  должно действовать везде: в аргументах, массивах, `enum`.

Рекомендация — первое.

### 2.4 `mut` у полей и `let` без `mut` — закрыто

**Решено:** `mut` у полей не пишется, изменяемость поля следует из
изменяемости переменной.

```
type Color {
    mut r: UByte                       // строки 4–6
    ...
}
let result: Color = { ... }            // строка 10 — без mut
```

Можно ли написать `result.r = 0`? Поле `mut`, а переменная — нет.
Варианты:

- мутабельность поля следует из мутабельности переменной (как в Rust),
  а `mut` у полей не пишется. Это самое простое правило;
- `mut` у поля значит «можно менять даже у `let`» — но тогда `let`
  перестаёт значить «неизменяемо», и компилятор не может положить
  глобальный `let` в `.rodata` (см. 4.7).

Рекомендация — первое, `mut` у полей убрать.

### 2.5 `UByte + UByte`: тип и переполнение — закрыто

**Решено:**

- Тип результата — тип операндов: `UByte + UByte` даёт `UByte`.
  Операнды разных типов — ошибка, нужен `as` (3.4).
- `+`, `-`, `*` и `++`/`--` всегда дают перенос по модулю 2ⁿ, у знаковых
  тоже (дополнительный код): `0xFF + 1` у `UByte` = `0x00`, `127 + 1` у
  `Byte` = `-128`. Отладочного режима с ловушкой нет.
- `+|`, `-|`, `*|` — с насыщением: результат прижимается к минимуму или
  максимуму типа. `0xFF +| 1` у `UByte` = `0xFF`, `0 -| 1` = `0`,
  `127 +| 1` у `Byte` = `127`.
- Цена: перенос у `UByte`/`UHalf` — одна `ANDI` (у `Byte`/`Half` —
  `SHLI` + `SARI`), у `Word`/`UWord` — ничего. Насыщение — три-четыре
  инструкции.

Пример: [examples/arith.m](../examples/arith.m).

Разбор, из которого выбирали:

`self.r + other.r` (строка 11) — какого это типа? В C оба операнда
повышаются до `int`, и сумма `0xFF + 0x01` = `0x100` не влезает обратно в
`UByte`. Нужно записать:

- **тип результата** — тип операндов (`UByte`), без повышений, как в
  Rust/Zig. Повышения из C тут только путают;
- **переполнение** — перенос по модулю 2⁸, ошибка или насыщение. Для
  цветов естественно насыщение, для счётчиков — перенос. Хорошая схема
  из Zig: `+` — перенос (или ловушка в отладочной сборке), `+|` —
  насыщение, `+%` — явный перенос.

На этой машине 8-битный перенос стоит одну лишнюю инструкцию
(`ANDI rd, rd, 0xFF`), а насыщение — три-четыре (сравнение и выбор).
Выбрать семантику нужно до кодогенерации, потому что от неё зависит,
когда маскировать результат.

### 2.6 `self` в обычной функции и `static` — закрыто

Решено:

- **ООП и методов в языке не будет.** `self` — обычное имя параметра,
  резервировать его не нужно.
- **Экспорт только явный, списком, как в JS.** По умолчанию всё в файле
  локально, наружу видно только то, что перечислено по имени:

  ```
  export { colorAdd, colorMix }
  ```

  Экспорта «всего сразу» нет. `static` больше не нужен:
  `static let colorAdd` из примера становится обычным `let colorAdd`,
  которого нет в списке `export`.

Подробные правила модулей — в 2.10.

### 2.7 Мелочи — закрыто

**Решено:**

- **Предупреждения нужны.** Компилятор предупреждает о:
  - локальной переменной, которую ни разу не прочитали;
  - `let mut`, в которую ни разу не записали после объявления (хватило
    бы `let`);
  - неэкспортированной функции, глобальной переменной или типе, которые
    нигде не используются;
  - импортированном имени, которое не используется;
  - коде после `return`, `break`, `continue` и бесконечного `while true`;
  - чтении `let mut x: T` без `=` до первой записи (3.6);
  - потерянном результате функции (ниже).

  О неиспользуемых параметрах — нет: у колбэков и обработчиков сигнатура
  задана снаружи, и часть параметров им не нужна.
- **Табы и пробелы — без разницы.** Для лексера оба — пробельные
  символы, отступы ничего не значат. Стиля по умолчанию язык не
  навязывает.

- **Результат функции нельзя молча потерять.** Вызов функции с
  результатом как отдельный оператор (`write(1, "hi\n", 3)`) — это
  предупреждение: ненужных результатов не бывает. Если результат не
  нужен, функция не должна его возвращать. Особого синтаксиса для
  сброса (`_ = f()`, `(void)f()`) нет. Это касается и встроенных
  функций: `atomicSwap(p, v)` без использования старого значения —
  предупреждение, для этого есть `atomicStore`.

Разбор:

- `let mut result` (строки 19, 28) и `let mut foo` (строка 53) нигде не
  меняются. Компилятор должен предупреждать.
- `let add` (строка 67) не используется. Нужен способ явно выбросить
  значение (`_ = ...`) и предупреждение о неиспользуемых переменных.
- `extern let puts(msg: *Byte): Void // "puts:" label`. Если это `puts`
  из libc, то он сам добавляет перевод строки (`puts("42")` +
  `puts("\n")` выведет пустую строку) и возвращает `int`. Если это своя
  функция на ассемблере — всё верно, но лучше назвать её иначе
  (`print`), чтобы не путать с C.
- В файле смешаны табы и пробелы (строки 3–7, 11–14, 51). Стоит сразу
  зафиксировать стиль, а потом сделать `m fmt`.

### 2.8 `if` без фигурных скобок — закрыто

**Решено:** тело `if`, `else`, `while` и `for` — это блок `{ }` или ровно
один оператор. Примеры: [examples/if.m](../examples/if.m),
[examples/loops.m](../examples/loops.m).

```
if n < 0 return 0
if flag == false flag = true
if n < 0 puts("-") else puts("+")
```

Правила, без которых парсер неоднозначен:

- **Условие (или диапазон у `for`) — самое длинное выражение после
  `if`, `while` или `in`.** Оно заканчивается
  на первом токене, которым выражение продолжиться не может, и с этого
  токена начинается оператор. Поэтому `if x -y` читается как
  `if (x - y) ...`, а не как `if x { -y }`.
- **Условие в скобках — как в C.** Если сразу после `if` или `while`
  стоит `(`, условие — ровно выражение в этих скобках, а тело начинается
  после `)`. Так однозначно пишется тело, которое начинается с `-`, `*`,
  `&`, `(` или `[`:

  ```
  if (p != null) *p = 0      // без скобок: p != (null * p) = 0 — ошибка
  if p != null { *p = 0 }    // или блок
  ```

  Обратная сторона: условие, которое лишь начинается со скобки,
  приходится брать в скобки целиком. `if (a + b) * c > 0 { }` — ошибка
  (условие `(a + b)`, тело `* c > 0`), нужно `if ((a + b) * c > 0) { }`
  или `if c * (a + b) > 0 { }`. Компилятор должен подсказывать это в
  сообщении об ошибке. Для `for` то же правило действует после `in`.
- **`else` относится к ближайшему `if` без `else`**, как в C. Чтобы
  привязать `else` к внешнему `if`, внутренний нужно взять в `{ }`.
- **Перевод строки ничего не значит:** тело можно перенести на следующую
  строку.
- **Тело-объявление (`if c let x = 1`) — ошибка:** переменная сразу
  выходит из области видимости.

Компилятору стоит предупреждать о теле без скобок, которое стоит на
отдельной строке с тем же отступом, что и `if` (ошибка в духе
`goto fail` из Apple SSL).

### 2.9 Диапазоны, `for mut` и шаг — закрыто

**Решено:**

- `a..b` — полуоткрытый диапазон (`b` не входит), `a...b` — закрытый
  (`b` входит). Записи отличаются одной точкой, и компилятор опечатку
  не заметит, поэтому в коде полуоткрытый — основной. Для лексера:
  `...` и `..` — отдельные токены, длинный проверяется первым. Число
  с точкой (`1.5`, если появится `Float`) — только когда после точки
  идёт цифра, иначе `0..argc` прочитался бы как `0.` и `.argc`;
- переменная `for` без `mut` неизменяема;
- `for mut i` разрешён, и изменение `i` в теле влияет на ход цикла, как
  в C;
- шаг задаётся словом `by`: `for i in 10...0 by -1`. Без `by` шаг равен 1.

Пример: [examples/ranges.m](../examples/ranges.m).

Семантика, которую нужно записать в спецификацию:

- Обе границы вычисляются один раз, до первой итерации.
- **Шаг** — целая константа, не ноль, по модулю влезающая в тип
  переменной. Константа нужна, чтобы направление было известно при
  компиляции. Знак задаёт направление, поэтому `by -1` работает и для
  беззнаковой переменной.
- **Пустой диапазон** — ноль итераций, а не ошибка. При шаге вверх
  диапазон пуст, если `a >= b` для `..` и `a > b` для `...`. При шаге
  вниз — наоборот.
- **Цикл никогда не переходит за границу и не переполняет `i`.** Для
  шага `k > 0` цикл `for mut i: T in a..b by k { тело }` — то же, что

  ```
  let mut i: T = a
  let end: T = b
  if i < end {
      while true {
          тело
          if i >= end break          // тело перепрыгнуло через end
          if end - i <= k break      // следующий шаг дошёл бы до end
          i = i + k
      }
  }
  ```

  Для `a...b` — то же самое, но с `<=` в первом `if` и с `end - i < k`
  во втором. Для шага вниз (`k < 0`) знаки сравнения меняются, а
  разность считается как `i - end`. Разность всегда неотрицательна,
  поэтому её считают в беззнаковом типе того же размера, и у знаковых
  типов она тоже не переполняется (`Byte`: `127 - (-128)` = 255 влезает
  в `UByte`).
- Отсюда:
  - `for i: UByte in 0...0xFF` делает 256 итераций и не зацикливается.
    В C-шном `for` с `<=` было бы переполнение;
  - `for i: UByte in 0xFF...0 by -3` останавливается на 0 и не уходит в
    `0xFD`;
  - если тело `for mut` прыгнуло дальше `end`, цикл заканчивается.
    Но если тело переполнило `i` (`i++` от `0xFF` у `UByte` даёт `0`,
    2.5), `i` снова меньше `end`, и цикл может не закончиться. Это
    ответственность программиста, как в C.
- Цена: две проверки на итерацию вместо одной. Для шага ±1 без `mut`
  компилятор может обойтись одной проверкой: `i` не меняется в теле и
  не может перепрыгнуть `end`.
- Обратный обход по индексам удобнее через полуоткрытый диапазон:
  `for i in argc..0 by -1`, индекс `i - 1`. Запись `argc - 1 ... 0 by -1`
  возвращает ошибку из 2.1.

### 2.10 Модули: `import` и `export` — закрыто

**Решено:**

- **Экспорт только явный:** `export { a, b }`. Его можно писать в любом
  месте файла и сколько угодно раз.
- **Импорт только по именам:** `import { a, b } from "file.m"`, без
  `import *`. Один и тот же файл можно импортировать несколько раз.
- **`as` работает в обе стороны:** `export { colorMix as mix }`,
  `import { colorGreen as green } from "color.m"`.
- **`extern` можно экспортировать.** Так сделано в
  [examples/externs.m](../examples/externs.m): файл объявляет
  ассемблерную `puts` и отдаёт объявление другим файлам. Экспорт
  значит «имя видно тому, кто импортирует», а не «файл определяет
  символ».
- **`main` экспортируется сама**, `export { main }` писать не нужно. Это
  единственное исключение из явного экспорта: `crt0` ищет глобальный
  символ `main`. Если в программе нет `main`, это ошибка линкера; если
  две — тоже. `export { main }` писать можно, но это ничего не меняет. (Сначала было выбрано «`main` экспортируется явно, без
  исключений», потом решение поменяли: писать это в каждой программе
  оказалось слишком шумно.)
- **Путь в `from` ищется:**
  1. относительно каталога текущего файла;
  2. затем по очереди в каталогах, переданных компилятору флагом `-I`
     (как `-I` у `cc` для `#include`). Так подключается стандартная
     библиотека, лежащая не рядом с программой:
     `m -I /opt/m/lib main.m` + `import { memcpy } from "rt/mem.m"`.
- **Ошибки компиляции:** экспорт имени, которого нет в файле; импорт
  имени, которое файл не экспортирует; два одинаковых имени в области
  видимости файла после импорта (например, импортировали `mix` и
  объявили свою `mix`).

Пример: [examples/modules/](../examples/modules/).

- **Типы экспортируются тем же `export`:** `export { Color }`.
- **Символ ELF равен экспортированному имени**, как в C. Неэкспортированные
  функции и переменные — локальные символы (`STB_LOCAL`), они не
  конфликтуют между файлами. Если две экспортированные `mix` из разных
  файлов попадают в одну программу, это ошибка линкера, и одну из них
  переименовывают через `export { colorMix as colorMix2 }`. У `import ... as`
  имя меняется только внутри файла, символ остаётся прежним.

## 3. Что спецификация языка должна зафиксировать — до

Это не ошибки примера, а решения, без которых нельзя писать парсер и
проверку типов.

### 3.1 Целочисленные типы и их размеры — закрыто

**Решено:** имена остаются, 64-битных типов нет — процессор 32-битный.

| M | C (ABI.md) | Размер / выравнивание | Знак |
|---|---|---|---|
| `Byte`, `UByte` | `signed char`, `unsigned char` | 1 / 1 | `Byte` знаковый |
| `Half`, `UHalf` | `short`, `unsigned short` | 2 / 2 | `Half` знаковый |
| `Word`, `UWord` | `int`, `unsigned int` | 4 / 4 | `Word` знаковый |
| `Bool` | `_Bool` | 1 / 1 | — |

- Строки и `argv` — `UByte`: `*UByte`, `*UByte[]`.
- `UWord` заменяет `size_t` и `uintptr_t`: указатель тоже 4 байта.
- Что из этого следует:
  - 64-битные счётчики `CYCLE`/`CYCLEH` и `INSTRET`/`INSTRETH`
    (INSTRUCTIONS, «Counters») читаются как два `UWord`, например в
    `type Cycles { lo: UWord, hi: UWord, }`. Сложение и сравнение таких
    пар пишется вручную или функцией рантайма;
  - C-функции с `long long` и `double` в сигнатуре через `extern` не
    вызвать. Это касается и `printf` с `%f`: вариадик-аргумент `float` в
    C повышается до `double`;
  - рантайму не нужны `__divdi3`, `__ashldi3`, `__floatdisf` и прочие
    64-битные функции из ABI.md.
- **`Float`** — 32-битный тип с плавающей точкой (`float` в C, 4 / 4).
  Живёт в обычных регистрах, инструкции `FADD`…`UTOF`. Литерал — `1.5`,
  `0.5`, `2.0` (точка и цифры с обеих сторон). Имя зарезервировано
  сейчас, а реализовать можно после целых. Деление на ноль даёт ±∞ или
  NaN (INSTRUCTIONS, «Floating point»), `Float as Word` насыщается.
  Пример: [examples/float.m](../examples/float.m).

Разбор, из которого выбирали:

`Word`, `UWord`, `Byte`, `UByte` — двусмысленные имена: у x86 `WORD`
занимает 16 бит, у ARM 32, у этой машины 32. Не ясно, как назвать
16- и 64-битные типы и знаковый ли `Byte` (для строк обычно берут
беззнаковый).

Если оставлять эти имена, в спецификации нужна таблица соответствия с C
ABI. Вариант с размером в имени для сравнения:

| M (вариант) | C (ABI.md)            | Размер / выравнивание | Регистры |
|-------------|-----------------------|-----------------------|----------|
| `I8`, `U8`   | `signed char`, `unsigned char` | 1 / 1  | 1 |
| `I16`, `U16` | `short`, `unsigned short`      | 2 / 2  | 1 |
| `I32`, `U32` | `int`, `unsigned int`          | 4 / 4  | 1 |
| `I64`, `U64` | `long long`                    | 8 / 8  | 2 (пара) |
| `ISize`, `USize` | `intptr_t`, `size_t`       | 4 / 4  | 1 |
| `F32`  | `float`                         | 4 / 4  | 1 (GPR) |
| `F64`  | `double`                        | 8 / 8  | 2, программно |
| `Bool` | `_Bool`                         | 1 / 1  | 1 |

Важно для кодогена:

- `I8`/`I16` при передаче в функцию расширяются до 32 бит по знаку, а
  беззнаковые — нулями (ABI, «Arguments»). Это делает вызывающий.
- 64-битные: сложение и вычитание — инлайн через `SLTU` для переноса,
  умножение — `MUL` + `MULHU` (ABI, «Runtime functions»), деление —
  `__divdi3` и т. п. из рантайма.
- `F32` — это обычные регистры и инструкции `FADD`…`UTOF`. Отдельного
  регистрового файла нет, поэтому аллокатор регистров общий.
- `F64` целиком программный (`__adddf3`…). Стоит сделать литералы с
  точкой типа `F32` по умолчанию, иначе каждый `1.5` будет тянуть
  программную арифметику.

### 3.2 Литералы — закрыто

**Решено:**

- **У целого литерала нет типа, пока его не задаст контекст:** тип
  переменной, параметра, другого операнда. `let a: UByte = 0xFF`,
  `a + 1`, `by -1` пишутся без `as`.
- **Константное выражение из одних литералов считается точно**, с
  произвольной точностью, и только результат приводится к типу
  контекста. Он обязан влезть в тип, иначе ошибка компиляции:
  `let x: UByte = 300`, `let y: UByte = 0x10 *| 0x10`,
  `let z: UByte = -1`. Перенос и насыщение (2.5) действуют только в
  рантайме, над типизированными значениями.
- **Литерал без контекста не встречается:** тип переменной всегда
  пишется явно (3.7).
- **Запись чисел:** десятичная, `0x…` и `0b…`. Разделитель `_` можно
  ставить между цифрами: `0xFD00_2000`, `0b1010_1010`, `1_000_000`.
  Восьмеричных литералов нет. Ведущий ноль у десятичного (`010`) —
  ошибка, чтобы его не прочитали как восьмеричный из C.
- **Символ** `'a'` — литерал типа `UByte`. Экранирование: `\n`, `\r`,
  `\t`, `\0`, `\\`, `\'`, `\"`, `\xNN`. В строках — то же.
- **Исходник в UTF-8, но в символах и строках разрешён только ASCII**
  (`0x20`–`0x7E` плюс экранирование). Остальные байты пишутся через
  `\xNN`: шрифт видеокарты — Windows-1252 (SPECIFICATION, «State at the
  entry point»), и `"\xE9"` — это `é` на экране. Тогда содержимое
  `.rodata` не зависит от кодировки, в которой сохранён файл.
- **Строка `"..."`** — байты в `.rodata` с завершающим нулём, тип
  `*UByte` (только чтение, 3.3).

Пример: [examples/literals.m](../examples/literals.m).

### 3.3 Указатели и мутабельность — закрыто

Сейчас `mut` есть у переменных, но не у указуемого значения. По сигнатуре
`f(p: *Color)` не видно, меняет ли `f` то, на что указывает `p`, и можно
ли передать туда адрес `let`-переменной или строкового литерала.

**Решено:**

- **`*T` — только чтение, `*mut T` — запись.** `&x` даёт `*T`, `&mut x`
  даёт `*mut T` и разрешён только у `let mut x`. Строковый литерал имеет
  тип `*UByte`, поэтому записать в него нельзя.
- **Изменяемость переменной и указуемого независимы:**

  | Объявление | Переставить `p` | Писать через `p` |
  |---|---|---|
  | `let p: *T` | нет | нет |
  | `let mut p: *T` | да | нет |
  | `let p: *mut T` | нет | да |
  | `let mut p: *mut T` | да | да |

- **`*mut T` неявно становится `*T`.** Это единственное неявное
  приведение в языке (3.4): оно только отнимает право записи. Обратно —
  только через `as`: `q as *mut T`. Это лазейка для MMIO и
  низкоуровневого кода, и в обычном коде её видно сразу.
- **Целое в указатель и обратно — через `as`:**
  `0xFD002000 as *mut UartRegs`, `p as UWord`.
- **Любой указатель может быть нулевым**, как в C, отдельного `?*T` нет.
  Нулевой указатель записывается словом `null`, оно подходит к любому
  `*T` и `*mut T`. Разыменование `null` — page fault: ядро держит первые
  8KB неотображёнными (ABI, «Entering the kernel»).
- Цена в рантайме нулевая: всё это только проверка типов.

Пример: [examples/pointers.m](../examples/pointers.m).

- **Разыменование — префиксная `*`, как в C:** `*p = 0`, `let x = *p`,
  `*dst = *src` (копия структуры целиком). Писать через `*p` можно только
  у `p: *mut T`. В `if` без блока тело с `*` требует скобок вокруг
  условия: `if (p != null) *p = 0` (2.8).
- **Индексация указателя — как в C:** `p[i]` у `*T` и `*mut T`, адрес
  элемента — `&p[i]` или `&mut p[i]`. Арифметики `p + i` нет. Индекс —
  любой беззнаковый тип (3.4), проверки границ нет.
- **`mut T[]` в параметре — массив, в который пишут.** `T[]` в
  параметре — то же, что `*T`, а `mut T[]` — то же, что `*mut T`. Типы
  совместимы в обе стороны, разница только в том, как читается
  сигнатура: `fill(buf: mut UByte[], n: UWord)` говорит «буфер из `n`
  элементов», `next(node: *mut Node)` — «один объект».

- **Поле через указатель — та же точка, что у значения**, как в Go и
  Zig: `p.r` при `p: *Color` — это `(*p).r`. Разыменовывается один
  уровень: у `pp: **Color` нужно `(*pp).r`. Писать `p.r = 1` можно
  только у `p: *mut Color`, так же как `c.r = 1` — только у `let mut c`.
  Стрелки `->` нет.
- **Массив сам становится указателем при передаче в параметр `T[]` или
  `mut T[]`**, как в C: `fill(buf, 16)`. Только при передаче в
  параметр — в остальных местах `T[N]` остаётся значением. В `mut T[]`
  можно передать только `let mut`-массив. Это второе неявное
  приведение после `*mut T` → `*T`.

### 3.4 Приведения типов — закрыто

**Решено:** неявных приведений нет совсем. Любая смена типа, даже
расширение без потерь (`UByte` → `UWord`), пишется через `x as T`.
Литералы под это правило не попадают: у них нет своего типа, пока его не
задаст контекст (3.2), поэтому `let x: UByte = 5` пишется без `as`.

Следствия:

- `UByte + UByte` даёт `UByte`, повышения до `Word`, как в C, нет (2.5);
- `UByte + UWord` — ошибка, нужно `(a as UWord) + b`;
- индекс массива — любой **беззнаковый** целый тип: `table[b]` при
  `b: UByte` пишется без `as`. Знаковый индекс — ошибка, нужен `as`;
- исключения: литералы (3.2), `*mut T` → `*T` и массив в параметр
  `T[]` (3.3), добавление `volatile` к указателю (4.1).

У приведений есть цена:

| Приведение          | Инструкции             |
|---------------------|------------------------|
| `Word as Float`     | `ITOF`                 |
| `Float as Word`     | `FTOI` (насыщающее, NaN → `0x7FFFFFFF`) |
| `UWord as UByte`    | `ANDI rd, rs, 0xFF`    |
| `UWord as Byte`     | `SHLI` + `SARI`        |
| `UByte as UWord`    | ничего, если компилятор держит `UByte` в регистре расширенным нулями (`LBU` так и загружает) |
| `*T as UWord`       | ничего                 |

То, что `FTOI` насыщает, а не даёт UB, как в C, — хорошее свойство: его
можно записать прямо в семантику языка.

### 3.5 Деление на ноль и сдвиги — закрыто

**Решено:** язык повторяет то, что делает процессор (INSTRUCTIONS,
«Register ALU», «Formats»). Это бесплатно и не оставляет UB.

- **Деление на ноль не ловушка:** `x / 0` — все единицы в типе
  (`0xFF` у `UByte`, `0xFFFFFFFF` у `UWord`, `-1` у знаковых), `x % 0` =
  `x`.
- **`MIN / -1`** у знаковых = `MIN`, `MIN % -1` = `0`. Это тот же
  перенос, что и у `+` (2.5).
- **Сдвиги:** значение сдвигается как 32-битное, от величины сдвига
  берутся младшие 5 бит, результат обрезается до типа. Отсюда:
  - `x << 33` == `x << 1` у любого типа;
  - у `UByte`: `0x81 << 1` = `0x02`, `x << 8` = `0`, `x >> 8` = `0`;
  - `>>` у знаковых — арифметический (`SAR`), у беззнаковых —
    логический (`SHR`).
- Величина сдвига — любой беззнаковый целый тип, как индекс (3.4).

Пример: [examples/arith.m](../examples/arith.m).

Разбор, из которого выбирали:

- Деление на ноль: процессор **не** генерирует исключение. `DIV` вернёт
  `0xFFFFFFFF`, `REM` вернёт делимое (INSTRUCTIONS, «Register ALU»).
  Варианты: зафиксировать в языке именно такой результат (бесплатно)
  или вставлять проверку и `BREAK`/панику (2 инструкции на деление).
  Выбрать нужно сразу, потому что это семантика, а не оптимизация.
- Сдвиг на ≥ 32: процессор берёт только младшие 5 бит (`x << 33` ==
  `x << 1`, INSTRUCTIONS, «Formats»). Язык может так и записать (это
  бесплатно), а для 8-, 16- и 64-битных типов правило придётся определить
  отдельно.

### 3.6 Инициализация — закрыто

**Решено:**

- **`let mut x: T` без `=` — переменная без начального значения:**
  `let mut buf: UByte[256]`. Компилятор ничего не обнуляет, в ней то,
  что лежало на стеке. Так пишутся буферы, которые всё равно
  перезапишут. Отдельного слова `undefined` нет.
- **`let x: T` без `=` и без `mut` — ошибка:** записать в неё потом
  нельзя, значит, у неё никогда не будет значения.
- Чтение до первой записи — не UB, а просто мусор. Компилятору стоит
  предупреждать, если он видит такое чтение.
- **Глобальная `let mut X: T` без `=`** лежит в `.bss`, а `.bss`
  обнуляет загрузчик или `crt0`. Поэтому у глобальных это нули, как в C.
- Поля, не названные в `{ .r = 1 }`, — нули, как в C. Поэтому `{}` —
  все нули.
- Пример: [examples/init.m](../examples/init.m).

- Литерал `{ ... }` без имени типа работает только там, где тип
  известен: у переменной, параметра, `return`, `*p = ...`. Так как вывода
  типов нет (3.7), тип известен всегда, и полная форма `Color { .r = 1 }`
  не нужна.

### 3.7 Вывод типов — закрыто

**Решено:** вывода типов нет, тип переменной всегда пишется явно:
`let red: Color = colorRed()`. Переменная цикла тоже:
`for i: UWord in 0..n`.

### 3.8 Выражения и операторы — закрыто

**Решено:**

- **`=`, `+=`, `-=` и прочие, `++`, `--` — операторы, а не выражения.**
  `a[i++] = i++`, `if x = 0`, `a = b = 0` не компилируются.
- **`&`, `|`, `^` связывают сильнее сравнений:** `x & MASK == 0` значит
  `(x & MASK) == 0`, а не ловушку из C.
- Аргументы функции вычисляются слева направо.
- `&&` и `||` — с коротким замыканием.

Приоритеты, от сильного к слабому (предложение, сверено с решениями
выше):

| Уровень | Операторы | Ассоциативность |
|---|---|---|
| 1 | `f()`, `a[i]`, `a.b` | слева |
| 2 | унарные `-`, `!`, `~`, `*`, `&`, `&mut` | справа |
| 3 | `as` | слева |
| 4 | `*`, `/`, `%`, `*\|` | слева |
| 5 | `+`, `-`, `+\|`, `-\|` | слева |
| 6 | `<<`, `>>` | слева |
| 7 | `&` | слева |
| 8 | `^` | слева |
| 9 | `\|` | слева |
| 10 | `==`, `!=`, `<`, `<=`, `>`, `>=` | нет: `a < b < c` — ошибка |
| 11 | `&&` | слева |
| 12 | `\|\|` | слева |
| 13 | `..`, `...` (только в `for`) | нет |

- `!` — логическое «не» для `Bool`, `~` — побитовое для целых.
- `as` сильнее арифметики: `a + b as UWord` = `a + (b as UWord)`,
  `-x as UWord` = `(-x) as UWord`.

Пример: [examples/expressions.m](../examples/expressions.m).

### 3.9 Тип «функция» — закрыто

**Решено:**

- Тип функции пишется как её сигнатура без имени, с именами
  параметров: `(a: Color, b: Color): Color`, `(): Void`. Имена служат
  документацией и на совместимость типов не влияют.
- Значение — указатель на код, 4 байта, как указатель на функцию в C.
  Его можно передать в `extern`-функцию и получить из ассемблера.
- Может быть `null`, как любой указатель. Вызов `null` — page fault при
  выборке инструкции.
- Имя функции — уже значение этого типа: `let f: (): Void = foo`, без
  `&`.

```
let mut func: (): Void = foo
func()
let mut handlers: ((frame: *mut TrapFrame): Void)[16]   // глобальная: все null
```

Пример: [examples/functions.m](../examples/functions.m).

**Псевдоним типа — `type Name = T`.** Длинный тип функции (и любой
другой) получает короткое имя:

```
type OpFunc = (left: Word, right: Word): Word
type Handler = (code: UWord): Void

let op: OpFunc = add
let apply(op: OpFunc, a: Word, b: Word): Word { return op(a, b) }
let mut handlers: Handler[16]
```

- Это именно псевдоним: `OpFunc` и `(left: Word, right: Word): Word` —
  один и тот же тип, `as` между ними не нужен.
- Подходит для любого типа: `type Uart = *volatile mut UartRegs`,
  `type Row = UByte[80]`.
- Для парсера это тот же `type`: после имени `{` — структура, `=` —
  псевдоним.
- Объявляется только на верхнем уровне, в любом порядке (5.1).
  Экспортируется как тип: `export { OpFunc }`.
- Псевдоним, который ссылается сам на себя (`type A = *A`), — ошибка:
  для самоссылки есть структура с полем-указателем.
- `packed` у псевдонима — ошибка: он ничего не объявляет, а только
  называет.

Отдельного «нового типа» (как `type PhysAddr = UWord`, который нельзя
смешивать с `UWord` без `as`) нет: при запрете неявных приведений он
потребовал бы `as` почти на каждой строке.

## 4. Чего не хватает для этой машины — вместе

Без этих пунктов на M можно писать только код, который ничего не знает о
железе. Ядро, драйверы и загрузчик придётся писать на ассемблере.

**Решено для всего раздела: встроенные функции — зарезервированные
имена без префикса**, как обычный вызов: `mfcr(N)`, `sizeof(T)`,
`atomicSwap(p, v)`. Объявить свою функцию или переменную с таким именем
нельзя. В разборе ниже они ещё записаны с `@` — так было в предложении.

Полный список зарезервированных имён:

| Группа | Имена |
|---|---|
| Управляющие регистры | `mfcr`, `mtcr` |
| Инструкции | `syscall`, `wfi`, `hlt`, `tlbi`, `fence`, `breakpoint` |
| Атомики | `atomicLoad`, `atomicStore`, `atomicSwap`, `atomicAdd`, `atomicCompareSwap` |
| Раскладка | `sizeof`, `alignof`, `offsetof` |

`breakpoint`, а не `break`: `break` — выход из цикла.

Ключевые слова из этого раздела: `volatile`, `asm`, `packed`, `align`.

### 4.1 Доступ к устройствам (MMIO) — закрыто

**Решено: квалификатор `volatile` в типе указателя**, как в C.

```
let uart: *volatile mut UartRegs = 0xFD00_2000 as *volatile mut UartRegs

while uart.status & UART_TX_READY == 0 {}
uart.data = c as UWord
```

Правила:

- `volatile` бывает только у указателя: `*volatile T` (только чтение) и
  `*volatile mut T`. Переменных `volatile` нет: общие с прерываниями
  данные защищают атомики (4.3).
- Каждое чтение и запись через такой указатель выполняется ровно один
  раз, в порядке исходного текста и ровно той ширины, что у типа поля
  (`UByte` — `LBU`/`SB`, `UWord` — `LW`/`SW`). Компилятор не выбрасывает,
  не объединяет и не переставляет их между собой.
- Квалификатор проходит через `.` и `&`: `&uart.status` имеет тип
  `*volatile UWord`. Признак не теряется при копировании указателя: он
  в типе, а не у переменной.
- Копия структуры целиком (`let s: UartRegs = *uart`) читает поля по
  одному, в порядке объявления, каждое своей ширины.
- `volatile` снимается только через `as`, а добавляется неявно:
  `*mut T` → `*volatile mut T`, `*T` → `*volatile T`. Это безопасное
  направление, как `*mut T` → `*T`: оно только запрещает оптимизации.
  Поэтому функцию `copyToDevice(dst: *volatile mut UByte, ...)` можно
  вызвать и для обычной памяти.

Пример: [examples/mmio.m](../examples/mmio.m).

Разбор, из которого выбирали:

Все устройства — это страницы `0xFD000000`–`0xFD009FFF`
(SPECIFICATION, «Memory map»). Чтение регистров имеет побочные эффекты:
у UART чтение `DATA` снимает байт из FIFO, а чтение `STATUS` сбрасывает
бит RX overflow (SPECIFICATION, «UART»). Компилятор не должен
выбрасывать, переставлять, объединять или дублировать такие обращения
и должен делать их ровно той ширины, что написана (устройства различают
`LW` и `LBU`).

Пока компилятор ничего не оптимизирует и каждое обращение к переменной
превращается в отдельную `LW`/`SW`, всё работает и так. Но правило
нужно заложить сразу, иначе первая же оптимизация (вынос чтения из
цикла, удаление «мёртвой» записи) сломает драйверы.

Альтернативы `volatile` из C:

| Подход | Где так сделано | Как выглядит в M | Сложность в компиляторе |
|---|---|---|---|
| **Квалификатор типа** (`volatile` из C) | C, C++, Zig (`*volatile T`) | `let uart: *volatile mut Uart = ...` | средняя: квалификатор проходит через всю систему типов, нужны правила для приведений и копирования структур |
| **Функции-интринсики чтения/записи** | Rust (`read_volatile`/`write_volatile`), Oberon (`SYSTEM.GET`/`SYSTEM.PUT`), Linux (`readl`/`writel`) | `@load(&uart.status)`, `@store(&uart.data, c)` | минимальная: один узел IR, который оптимизатор не трогает; тип — обычный указатель |
| **Атрибут у переменной или поля** | Ada (`Volatile`, `Address`) | `@mmio(0xFD002000) let uart: Uart` — каждое обращение к полям `uart` обязательно | небольшая: признак у символа, а не у типа |
| **Типы-обёртки регистров** | Rust embedded (`VolatileCell`, `tock-registers`, svd2rust) | `status: Reg<UWord>` с методами `read()`/`write()` | не подходит: методов в M не будет (2.6) |
| **Отдельные инструкции ввода-вывода** | x86 (`in`/`out`) | — | на этой машине неприменимо: устройства в общем адресном пространстве |

**Рекомендация.** Начать с интринсиков `@load`/`@store`: в компиляторе
это почти ничего не стоит, и они явно видны в коде. Квалификатор типа
у C протекает повсюду (`volatile`-структуры, копии, приведения), и это
источник ошибок. Когда драйверов станет много, поверх интринсиков можно
сделать атрибут `@mmio` у глобальной переменной (как в Ada), который
превращает каждое обращение к её полям в `@load`/`@store`:

```
type UartRegs {
    data:    UWord,    // 0x00
    status:  UWord,    // 0x04
    control: UWord,    // 0x08
}

let UART_TX_READY: UWord = 1 << 1
let uart: *mut UartRegs = 0xFD002000 as *mut UartRegs

let putc(c: UByte): Void {
    while @load(&uart.status) & UART_TX_READY == 0 {}
    @store(&uart.data, c as UWord)
}
```

### 4.2 Специальные инструкции: интринсики или ассемблерная вставка — закрыто

**Решено:** интринсики плюс простая вставка без операндов.

| Интринсик | Инструкция | Замечание |
|---|---|---|
| `mfcr(N): UWord` | `MFCR rd, N` | `N` — константа: кодируется в `imm14` |
| `mtcr(N, x: UWord): Void` | `MTCR N, rx` | то же |
| `syscall(n, a1, ..., a6): Word` | аргументы в `r1`–`r6`, номер в `r9` | от 0 до 6 аргументов типа `UWord`/`Word`/указатель |
| `wfi()`, `hlt()` | `WFI`, `HLT` | |
| `tlbi(addr: UWord)` | `TLBI` | |
| `fence()` | `FENCE` | |
| `breakpoint()` | `BREAK` | |

- `asm { "wfi" "nop" }` — одна или несколько строк, каждая — строка
  ассемблера. Компилятор копирует их в вывод и обращается со вставкой
  как с вызовом функции: считает, что она портит память и все
  caller-saved регистры. Операндов нет.
- Всё, что сложнее, — функции на ассемблере и `extern`.
- Вход в обработчик прерываний пишется целиком на ассемблере: он
  сохраняет регистры в кадр и вызывает функцию M
  `trap(frame: *mut TrapFrame)`, а потом делает `IRET`.

Пример: [examples/cpu.m](../examples/cpu.m).

Разбор, из которого выбирали:

Инструкции, которые нельзя выразить на C-подобном языке:

| Инструкция | Зачем |
|---|---|
| `MFCR`/`MTCR` | `STATUS`, `IVEC`, `EPC`, `CAUSE`, `PTBR`, `SCRATCH`, счётчики |
| `SYSCALL` | обёртки системных вызовов (номер в `r9`, аргументы в `r1`–`r6`) |
| `WFI`, `HLT` | idle-цикл ядра, остановка |
| `TLBI` | смена отображения страниц |
| `IRET` | возврат из обработчика |
| `FENCE` | порядок обращений к памяти при DMA |
| `BREAK` | паника, `assert`, точки останова |
| `LL`/`SC` | атомики (4.3) |

Есть четыре способа, от простого к сложному. Их не нужно выбирать
навсегда: каждый следующий добавляется поверх предыдущего.

**1. Функции на ассемблере и `extern`. Работает уже сейчас.**

```
; m/rt/cpu.asm
wfi:        wfi
            ret
mfcr_status:
            mfcr r1, status
            ret
```

```
extern let wfi(): Void
extern let mfcr_status(): UWord
```

Аргументы и результат идут через `r1`–`r8` по ABI, поэтому компилятору
ничего не нужно знать. Цена — `call` + `ret` (2 инструкции и сброс
конвейера на переходах). Для `WFI` и `TLBI` это неважно. Для
`MFCR`/`MTCR` нужна отдельная функция на каждый регистр: номер
регистра — это `imm14` инструкции, а не значение в регистре.

**2. Простая ассемблерная вставка без операндов.**

```
asm { "wfi" }
asm { "fence" }
```

Компилятор выдаёт ассемблерный текст для `asm.py`, поэтому вставка —
это просто копирование строки в вывод. Сложность возникает, только
когда вставке нужны значения из переменных: компилятор не знает, в
каком регистре что лежит, и что вставка испортит. Без операндов
компилятор должен считать, что вставка меняет память и все
caller-saved регистры (`r1`–`r9`, `r31`), то есть обращаться с ней как
с вызовом функции. Годится для `WFI`, `HLT`, `FENCE`, `BREAK`.

**3. Интринсики.**

```
let s: UWord = @mfcr(CR_STATUS)
@mtcr(CR_STATUS, s | STATUS_IE)
let r: Word = @syscall(SYS_WRITE, fd, buf, len)
@wfi()
@tlbi(addr)
let old: UWord = @atomicSwap(&lock, 1)
```

Как добавить:

1. Лексер: токен `@name` (или зарезервированные имена).
2. Парсер: `@name(args)` — обычный вызов, но узел AST — `Intrinsic`, а
   не `Call`.
3. Проверка типов: у каждого интринсика фиксированная сигнатура в
   таблице компилятора. Аргумент `@mfcr`/`@mtcr` с номером регистра
   должен быть константой времени компиляции: он кодируется в `imm14`.
4. Кодогенерация: свой шаблон на каждый интринсик:

   | Интринсик | Код | Портит |
   |---|---|---|
   | `@mfcr(N)` | `mfcr rd, N` | ничего |
   | `@mtcr(N, x)` | `mtcr N, rx` | ничего, но порядок с памятью сохраняется |
   | `@syscall(n, a, b, c)` | `a`→`r1`, `b`→`r2`, `c`→`r3`, `n`→`r9`, `syscall` | `r1`, `r2` (ABI, «System calls») |
   | `@wfi()` | `wfi` | ничего |
   | `@atomicSwap(p, v)` | цикл `ll`/`sc`/`bnez` | временный регистр |

Компилятор точно знает, что делает каждый интринсик, поэтому не
сохраняет лишние регистры и может оптимизировать код вокруг. В этом их
главное преимущество перед вставкой.

**4. Ассемблерная вставка с операндами** (как `asm` в GCC или `asm!` в
Rust):

```
asm { "mfcr {out}, status", out = out(reg) s }
asm { "mtcr status, {in}", in = in(reg) s }
```

Компилятор сам выбирает регистры под `{out}`/`{in}`, подставляет их в
текст и знает, что портит вставка. Это самый гибкий вариант, но он
требует, чтобы аллокатор регистров понимал ограничения. В
неоптимизирующем компиляторе (все переменные на стеке) это проще:
загрузить операнды в `r1`, `r2`… перед вставкой и сохранить результаты
после.

**Рекомендация.** Сейчас — способ 1: он уже работает и покрывает всё,
кроме дешёвого `MFCR`/`MTCR`. С первой версией компилятора — способ 2:
это несколько строк кода. Затем интринсики для `MFCR`/`MTCR`,
`SYSCALL` и атомиков, где важны константа в `imm14`, фиксированные
регистры и цикл `LL`/`SC`. Вставку с операндами можно не делать
вообще. Rust и Zig пришли к той же схеме: интринсики для частых случаев,
вставка — для редких.

Отдельный случай — вход в обработчик прерываний. Он стартует без
свободных регистров и не может доверять `sp` (ABI, «Entering the
kernel»). Ни вставка, ни интринсики тут не помогут: вход пишется
целиком на ассемблере. Он сохраняет регистры в кадр и вызывает обычную
функцию M `trap(frame: *mut TrapFrame)`, а потом делает `IRET`.

### 4.3 Атомики — закрыто

**Решено:** интринсики над `Word`, `UWord` и указателями, компилятор
разворачивает их в цикл `LL`/`SC`. Для других типов — ошибка компиляции.
Адрес должен быть выровнен на 4 (иначе исключение, как у `LL`).

| Интринсик | Что делает | Возвращает |
|---|---|---|
| `atomicLoad(p)` | читает `*p` | значение |
| `atomicStore(p, v)` | пишет `v` в `*p` | `Void` |
| `atomicSwap(p, v)` | пишет `v` | старое значение |
| `atomicAdd(p, v)` | прибавляет `v` (с переносом) | старое значение |
| `atomicCompareSwap(p, expected, v)` | пишет `v`, только если `*p == expected` | старое значение; успех, если оно равно `expected` |

`p` — `*mut T` для записи и `*T` для `atomicLoad`.

`atomicCompareSwap` — то, что в x86 называется `cmpxchg`, а в C11 —
`atomic_compare_exchange`: «сравнить и заменить». На нём строятся
lock-free списки и счётчики со сложным условием.

На одноядерной машине `atomicLoad`/`atomicStore` выровненного слова —
это обычные `LW`/`SW`, но компилятор не переставляет их с другими
обращениями к памяти.

Пример: [examples/cpu.m](../examples/cpu.m).

Разбор, из которого выбирали:

У процессора есть только `LL`/`SC`, без смещения, только для
выровненного слова (INSTRUCTIONS, «Atomic word operations»). Языку
нужны `@atomicLoad`, `@atomicStore`, `@atomicSwap`, `@atomicAdd`,
`@cmpxchg` для слов и указателей. Компилятор разворачивает их в цикл
`LL`/`SC`. Атомики на байтах и 64-битных значениях — ошибка компиляции.

Машина одноядерная, но атомики всё равно нужны: прерывание может прийти
между чтением и записью. Пока интринсиков нет, их можно сделать
функциями на ассемблере (способ 1 из 4.2).

### 4.4 Секции, выравнивание, линковка — закрыто

**Решено:**

- **`section` пока не нужен:** код, которому нужна своя секция (вход
  boot-образа, вход в обработчик прерываний, таблица fixup'ов), пишется
  на ассемблере. Добавить можно потом, ничего не сломав.
- **`align(N)` — слово-модификатор перед глобальной переменной:**
  `align(4096) let mut pageDir: UWord[1024]`. `N` — константа, степень
  двойки, не меньше естественного выравнивания типа. У локальных
  переменных — ошибка: `sp` выровнен только на 8 (ABI, «Stack»), и
  выравнивать кадр под 4096 слишком дорого.

- `@name("symbol")` не нужен: у `extern` символ равен имени, при экспорте
  имя меняется через `as` (2.10).
- Символы линкера объявляются как `extern let __bss_start: UByte`, а
  используется их адрес: `&__bss_start`. Пример:
  [examples/globals.m](../examples/globals.m).

Разбор:

- `@section(".text.boot")` — чтобы положить точку входа в начало
  образа, а таблицы — в свои секции (ABI упоминает таблицу fixup'ов для
  `copy_from_user`).
- `@align(4096)` для таблиц страниц: `PTBR` и PTE указывают на
  выровненные по странице таблицы (INSTRUCTIONS, «Page tables»).
- `@name("symbol")` — управление именем символа. Комментарий
  `// "puts:" label` в примере — как раз потребность в таком атрибуте.
- `extern`-переменные: `extern let __bss_start: UByte`, чтобы стартовый
  код мог обнулить `.bss` (ABI, «Program entry»: boot-образ делает это
  сам).

### 4.5 Раскладка структур — закрыто

**Решено:**

- Раскладка как в C (ABI, «Data types»): поля по порядку, каждое на
  своём выравнивании, размер кратен наибольшему выравниванию.
  Компилятор поля не переставляет.
- **`packed type`** — структура без отступов: поля идут вплотную,
  выравнивание структуры — 1, размер — сумма размеров полей.
  Невыровненные поля компилятор читает и пишет побайтово (`LBU`/`SB` +
  сдвиги): невыровненный `LW` — исключение (`CAUSE` 3/4).
- Адрес невыровненного поля упакованной структуры (`&h.length`) взять
  нельзя — ошибка компиляции: через такой указатель обычный `LW` упадёт.
- `sizeof(T)`, `alignof(T)`, `offsetof(T, field)` — константы времени
  компиляции.
- Битовых полей нет: флаги PTE и `STATUS` — константы и `|`, `&`, `<<`.

Пример: [examples/layout.m](../examples/layout.m).

Разбор:

- По умолчанию — раскладка как в C (ABI, «Data types»): поля по порядку,
  каждое на своём выравнивании. Тогда структуры M совместимы с C и
  ассемблером без атрибутов. Переставлять поля ради размера не нужно:
  это ломает MMIO и `TrapFrame`.
- `packed` — без выравнивания. Невыровненный доступ на этой машине — это
  исключение (`CAUSE` 3/4), поэтому компилятор должен читать
  невыровненные поля побайтово (`LBU` + сдвиги). Это стоит записать
  явно.
- `sizeof(T)`, `alignof(T)`, `offsetof(T, field)` — для ассемблерных
  частей ядра, которым нужны смещения в `TrapFrame`.
- Флаги PTE (`R/W/X/U/A/D/G`) и `STATUS` (`IE`, `PIE`, `UM`, `PUM`,
  `EXL`): битовые поля или `enum` с операторами `|`, `&`.

### 4.6 Точка входа — закрыто

**Решено:** язык о точке входа ничего не знает, это дело рантайма.
`crt0` на ассемблере вызывает экспортированную `main` и передаёт
результат в `exit`. У boot-образа свой `crt0`.

Во второй версии примера всё сделано правильно: пользователь пишет
только `main`, а `crt0` из рантайма разбирает блок процесса (`argc`,
`argv`, `envp`, auxv — ABI, «Process start»), вызывает `main` и передаёт
результат в `exit`. `crt0` пишется на ассемблере: при входе `sp`
указывает на данные, а не на свободный стек, и обычная функция M так
стартовать не может.

Для boot-образа нужен отдельный `crt0`: там `r1` = адрес boot info
block (`0x00001000`), `.bss` никто не обнулил, а `ra` = 0, так что
возвращаться некуда (SPECIFICATION, «State at the entry point»). Этот
`crt0` обнуляет `.bss`, вызывает `main(info: *BootInfo)` и после неё
делает `HLT` или выключает машину через power controller.

### 4.7 `let` вместо `const` и глобальные переменные — закрыто

**Решено:** у глобальной переменной (`let` и `let mut`) инициализатор —
только константное выражение: литералы, арифметика над ними, другие
глобальные `let`-константы, `as` от константы, `{ ... }` из констант,
адрес другой глобальной переменной или функции (его подставит линкер).
Вызов функции — ошибка. `crt0` ничего не вычисляет до `main`.
Пример: [examples/globals.m](../examples/globals.m).

Разбор, из которого выбирали:

`let` без `mut` действительно может играть роль `const`: так сделано в
Swift (`let`) и Zig (`const`). Отдельное ключевое слово не нужно. Но
«неизменяемое» и «известное при компиляции» — это разные свойства:

```
let A: UWord = 4096                 // известно при компиляции
let red: Color = colorGetRed()      // неизменяемо, но вычисляется при запуске
```

`A` можно использовать как размер массива, как номер регистра в
`@mfcr(A)`, в метке `match`, в инициализаторе другой глобальной
переменной. `red` — нельзя. Поэтому спецификация должна сказать:

- **Когда `let` — константа времени компиляции.** Простое правило (как
  в Zig): если инициализатор — константное выражение (литералы,
  арифметика над ними, другие такие же `let`, `sizeof`), то значение
  известно компилятору. Иначе это просто неизменяемая переменная.
- **Глобальный `let` — только с константным инициализатором.** Иначе
  кто-то должен вычислить его до `main`, как конструкторы глобальных
  объектов в C++. Это лишний код в `crt0` и неочевидный порядок
  инициализации между модулями. Лучше запретить.
- **Есть ли у глобального `let` адрес.** Если `&A` или `extern`-доступ из
  другого модуля разрешены, значение нужно положить в `.rodata` как
  символ. Компилятор при этом всё равно подставляет значение прямо в код
  (`addi`/`lui`+`ori`), а символ остаётся для тех, кому нужен адрес.
- **Куда идут глобальные переменные:**

  | Объявление | Секция |
  |---|---|
  | `let X: T = константа` | `.rodata` (или нигде, если адрес не берут) |
  | `let mut X: T = константа ≠ 0` | `.data` |
  | `let mut X: T = 0` или без `=` | `.bss` |
  | `@threadLocal let mut X: T` | `.tdata`/`.tbss`, доступ через `tp` (`%tprel`) |

- **`let` с указателем** неизменяем только сам по себе:
  `let uart: *mut UartRegs = 0xFD002000 as *mut UartRegs` — адрес
  константный, но регистры через него менять можно.

### 4.8 Ограничения кодогенерации

**Решено:** вариадических функций пока нет, даже у `extern`: `double` и
`long long` в языке нет, а libc на машине пока нет. `...` можно
добавить потом, ничего не сломав.

Это не синтаксис, но компилятор должен учитывать их с первого дня:

- `imm14` — это ±8KB. Кадр стека больше 8KB и поле дальше 8KB
  адресуются через `r9` (ABI, «Stack»). Константы за пределами
  ±8KB — через `LUI` + `ORI`.
- Условный переход достаёт на ±32KB. Дальше — инвертированный переход
  через `JAL`. `JAL` достаёт на ±1MB, дальше — линкерные veneer'ы через
  `r9` (ABI, «Linker veneers»). Поэтому `r9` нельзя держать живым через
  вызов.
- `sp` выровнен на 8 при каждом вызове, red zone нет.
- Структура до 8 байт идёт в регистрах, больше — по адресу копии.
  Возврат больше 8 байт — через скрытый первый аргумент в `r1`.
- Вариадик-аргументы при вызове C-функций идут **только через стек**,
  даже если регистры свободны. `F32` повышается до `F64`, 8- и 16-битные
  — до 32 бит. Нужен синтаксис `extern let printf(fmt: *UByte, ...): Word`.
- Копирование больших структур — через `memcpy`/`memset`. Ядро без libc
  должно их предоставить (ABI, «Runtime functions»).

## 5. Чего не хватает как языку вообще

### 5.1 Нужно для первой версии — закрыто

- **`Bool`** — `Bool` занимает 1 байт, `true` = 1, `false` = 0, в целое —
  через `as`. Условие `if`, `while` и операнды `&&`, `||`, `!` — только
  `Bool`: `if p != null`, `if n != 0`. `if p` и `if n` — ошибки.
- **Порядок объявлений верхнего уровня — любой**, как в Go и Zig:
  функция может вызвать ту, что объявлена ниже, тип поля может быть
  объявлен ниже, глобальная константа может ссылаться на константу
  ниже. Предварительных объявлений нет. Ошибки: цикл в константах
  (`let A: UWord = B`, `let B: UWord = A`) и структура, которая содержит
  саму себя по значению (через указатель — можно). Внутри функции
  порядок обычный: переменная видна только после объявления.
  Пример: [examples/order.m](../examples/order.m).
- **Литерал массива — `[1, 2, 3]`.** Запятые — как в 2.3, последняя
  необязательна. Не названные элементы — нули, как поля у структуры:
  `let a: UByte[8] = [1, 2]` — это `1, 2, 0, 0, 0, 0, 0, 0`, а `[]` — все
  нули. Элементов больше, чем `N`, — ошибка. Тип всегда известен из
  контекста (3.7). Пример: [examples/arrays.m](../examples/arrays.m).
- **`break` и `continue` — без меток**, как в C. Выйти сразу из двух
  циклов можно через флаг или `return` из отдельной функции.
- **Бесконечный цикл — `while true`**, отдельного `loop` нет. Компилятор
  считает `while true` без `break` бесконечным: после него не нужен
  `return`, даже если функция что-то возвращает.
  Пример: [examples/loops.m](../examples/loops.m).
- **`enum` с базовым типом:**

  ```
  enum Cause: UWord {
      Interrupt = 0,
      Syscall   = 12,
  }
  ```

  - базовый тип — целый;
  - значения, как в C: первый элемент без `=` равен 0, каждый следующий
    без `=` — предыдущему плюс 1. Явное значение можно поставить у любого
    элемента, и счёт продолжается от него:

    ```
    enum Key: UByte {
        None,          // 0
        Escape,        // 1
        Enter,         // 2
        F1 = 0x70,     // 0x70
        F2,            // 0x71
        F3,            // 0x72
    }
    ```

  - значение, которое не влезает в базовый тип, — ошибка, в том числе
    полученное автоматически;
  - элемент пишется с именем типа: `Cause.Syscall`;
  - в целое и обратно — через `as`: `c as UWord`, `n as Cause`.
    Обратное приведение не проверяется: в `Cause` может оказаться
    значение, которого нет в списке, — как в C;
  - одинаковые значения у двух элементов — ошибка;
  - экспортируется как тип: `export { Cause }`;
  - размер и выравнивание — как у базового типа.

  Пример: [examples/enums.m](../examples/enums.m).
- **`switch` — как в C**, с `case`, `default`, `break` и проваливанием:

  ```
  switch cause {
      case Cause.Syscall:
          handleSyscall(frame)
          break
      case Cause.LoadPageFault:
      case Cause.StorePageFault:
          handleFault(frame)
          break
      default:
          panic("unknown cause")
  }
  ```

  - выражение без скобок, как у `if`; тело в `{ }`;
  - `switch` по целым и `enum`, метки `case` — константы, одинаковые
    метки — ошибка;
  - без `break` выполнение проваливается в следующий `case`;
  - полнота не проверяется;
  - `let` прямо в теле `case` — ошибка: в C из-за этого можно перепрыгнуть
    инициализацию. Переменную объявляют в блоке: `case 1: { let x ... }`;
  - **`break` внутри `switch` выходит из `switch`, а не из цикла**, как в
    C. Меток нет, поэтому выйти из цикла изнутри `switch` можно только
    через флаг или `return`. `continue` внутри `switch` относится к
    циклу.

  Пример: [examples/switch.m](../examples/switch.m).
- **`Never` нет.** `panic` и `exit` объявляются как `Void`. После вызова
  такой функции в функции с результатом компилятор всё равно требует
  `return`: его пишут, даже если до него не дойдут. Бесконечный цикл
  `while true` этого не требует (см. выше).
- **Модули и импорт** — решено в 2.10.
- **Комментарии** — `//` до конца строки; `/* */` блочные и вложенные,
  как в Rust (`/* /* */ */` закрывается правильно); `///` —
  doc-комментарий, стоит прямо перед объявлением (функция, `type`, поле,
  глобальная переменная) и описывает его. `///` в другом месте —
  предупреждение. Пример: [examples/comments.m](../examples/comments.m).
- **`sizeof`/`alignof`/`offsetof`** — решено в 4.5.

### 5.2 Можно позже — отложено

**Решено:** ничего из этого списка в первую версию не входит. Каждый
пункт можно добавить потом, не ломая уже написанный код.

- **`defer`** — освобождение ресурсов и снятие блокировок в ядре. Дёшево
  в компиляторе, сильно сокращает ошибки.
- **Обработка ошибок.** ABI возвращает ошибки как `-errno` (−4095…−1).
  Можно сделать тип-результат в духе Zig (`!T`), который на уровне ABI
  остаётся одним регистром для `T` размером в слово.
- **Tagged union** (`enum` с данными).
- **Обобщённые типы** — хотя бы для контейнеров. Можно долго жить без
  них, если есть срезы.
- **Вычисления при компиляции** — для таблиц (например, `font.asm` и
  палитра).
- **Аллокатор** — библиотека, а не язык. Язык не должен зависеть от кучи.

## 6. Пример с учётом рекомендаций

Иллюстрация того, как решения из разделов 2–4 выглядят в коде. Всё,
что уже решено, — в [examples/](../examples/), по файлу на тему.

```
extern let print(msg: *UByte): Void           // своя функция на ассемблере

type Color {
    r: UByte,                                // mut у полей не нужен
    g: UByte,
    b: UByte,
}

let RED:   Color = { .r = 0xFF }             // константы: .g и .b — нули
let GREEN: Color = { .g = 0xFF }

let colorAdd(a: Color, b: Color): Color {   // не в export — локальная
    let c: Color = {
        .r = a.r +| b.r,                     // с насыщением
        .g = a.g +| b.g,
        .b = a.b +| b.b,
    }
    return c
}

let printArgs(argc: UWord, argv: *UByte[]): Void {
    for i: UWord in 0..argc {               // полуоткрытый, argc = 0 безопасен
        print(argv[i])
        print("\n")
    }
}

let main(argc: UWord, argv: *UByte[]): Word {
    print("Hello, M!\n")

    let foo: Word = 42
    if foo == 42 {
        print("42")
    } else if foo > 42 {
        print("> 42")
    } else {
        print("< 42")
    }
    print("\n")

    printArgs(argc, argv)

    let yellow: Color = colorAdd(RED, GREEN) // тип всегда явно (3.7)
    return 0
}
                                             // main экспортируется сама,
                                             // остальное в файле — локальное
```

И ядро — то, что раньше на M было не написать:

```
let CR_STATUS: UWord = 0                     // INSTRUCTIONS, «Control registers»
let STATUS_IE: UWord = 1 << 0

let enableInterrupts(): Void {
    mtcr(CR_STATUS, mfcr(CR_STATUS) | STATUS_IE)
}

let idle(): Void {
    while true wfi()
}
```

`mfcr(CR_STATUS)` компилируется в одну `mfcr rd, 0`: номер регистра
известен при компиляции, потому что `CR_STATUS` — это `let` с
константным инициализатором (4.7).
