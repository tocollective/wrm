# 5. Операторы

[← Выражения](04-expressions.md) · [Оглавление](README.md) · [Модули →](06-modules.md)

## 5.1 Операторы и их границы

Тело функции — последовательность операторов:

| Оператор | Пример |
|---|---|
| объявление переменной | `let mut i: UWord = 0` |
| объявление функции | `let twice(x: Word): Word { ... }`, `let mut f(): Void { ... }` ([3.8](03-declarations.md#38-вложенные-функции-и-литералы)) |
| присваивание | `x = 1`, `p.r = 0`, `*p = 0`, `a[i] = v` |
| составное присваивание | `i += 2`, `flags \|= MASK` |
| `++`, `--` | `i++` |
| вызов | `puts("hi")` |
| блок | `{ ... }` |
| `if` / `else` | 5.5 |
| `while` | 5.6 |
| `for` | 5.7 |
| `switch` | 5.9 |
| `break`, `continue` | 5.8 |
| `return` | 5.10 |
| `asm` | [7.4](07-hardware.md#74-asm) |

Точки с запятой нет, и переводы строк ничего не значат. Оператор
заканчивается там, где его грамматика больше не может продолжиться.
Поэтому `x = a` и следующая строка `-b` — это `x = a - b`. Оператор,
который начинается с `-`, `*`, `&`, `(` или `[`, после выражения без
скобок нужно отделять блоком или скобками (5.5).

Другие выражения как оператор — ошибка: `x + 1` или `a == b` в
отдельной строке ничего не делают.

## 5.2 Блок

`{ операторы }` — новая область видимости
([3.7](03-declarations.md#37-область-видимости-и-порядок)). Пустой блок
`{}` допустим.

## 5.3 Присваивание

```
место = выражение
место op= выражение     // op: + - * / % & | ^ << >>
место++
место--
```

- **Это операторы, а не выражения:** у них нет значения. `a = b = 0`,
  `let j: UWord = i++`, `buf[i++] = 0`, `if x = 0` — ошибки.
- `место` — изменяемая переменная, её поле или элемент; `*p`, `p.f`,
  `p[i]` при `p: *mut T`
  ([4.4](04-expressions.md#44-постфиксные-операторы)).
- Тип справа совпадает с типом места (с учётом неявных приведений и
  литералов).
- `x op= y` — то же, что `x = x op y`, но адрес `x` вычисляется один
  раз. Для `<<=`, `>>=` правая часть — любой беззнаковый тип, как у
  сдвигов.
- `x++`, `x--` — `x += 1`, `x -= 1`, с переносом. Есть только
  постфиксная форма. У `Float`, указателей и `enum` их нет.
- С насыщением составного присваивания нет: `x = x +| 1`.
- Структуру и массив можно присвоить целиком: `*dst = *src`, `c = {}`.

## 5.4 Вызов как оператор

`f(args)` в отдельной строке. Если функция что-то возвращает и результат
теряется — **предупреждение**: ненужных результатов не бывает. Особой
записи, чтобы выбросить результат, нет. Результат используют:

```
if write(1, "hi\n", 3) < 0 breakpoint()
```

Правило действует и для встроенных функций: `atomicSwap(p, v)` без
использования старого значения — предупреждение, для простой записи есть
`atomicStore`.

## 5.5 `if` / `else`

```
if условие тело
if условие тело else тело
```

- **Условие — только `Bool`:** `if p != null`, `if n != 0`. `if p` и
  `if n` — ошибки.
- **Тело — блок `{ }` или ровно один оператор.** `else if` — это `else`,
  телом которого стал другой `if`.

  ```
  if n < 0 return 0
  if n < 0 puts("-") else puts("+")
  if a {
      ...
  } else if b {
      ...
  } else {
      ...
  }
  ```

- **Тело-объявление** (`if c let x: UWord = 1`,
  `if c let f(): Void { }`) — ошибка: имя сразу вышло бы из области
  видимости.

### Где кончается условие

1. **Если сразу после `if` стоит `(`**, условие — ровно выражение в этих
   скобках, как в C. Тело начинается после `)`:

   ```
   if (p != null) *p = 0
   ```

   Поэтому условие, которое только **начинается** со скобки, берут в
   скобки целиком: `if (a + b) * c > 0 { }` — ошибка (условие
   `(a + b)`, тело `* c > 0`). Нужно `if ((a + b) * c > 0) { }` или
   `if c * (a + b) > 0 { }`. Компилятор подсказывает это в сообщении об
   ошибке.
2. **Иначе условие — самое длинное выражение** после `if`. Оно
   заканчивается на первом токене, которым выражение продолжиться не
   может; с этого токена начинается тело. `if x -y` — это `if (x - y)`,
   а не `if x { -y }`.

Тело, которое начинается с `-`, `*`, `&`, `(` или `[`, пишут в блоке или
ставят условие в скобки (правило 1):

```
if p != null *p = 0        // ошибка: p != (null * p) = 0
if (p != null) *p = 0      // так
if p != null { *p = 0 }    // или так
```

### Висячий `else`

`else` относится к ближайшему `if` без `else`. Чтобы привязать его к
внешнему `if`, внутренний берут в блок:

```
if a
    if b f() else g()       // else — от if b

if a {
    if b f()
} else {
    g()                     // else — от if a
}
```

Компилятор предупреждает, если тело без скобок стоит на отдельной строке
с тем же отступом, что и `if`: это похоже на ошибку.

Пример: [examples/if.m](../../examples/if.m).

## 5.6 `while`

```
while условие тело
```

- Условие — `Bool`, правила границ — как у `if` (5.5).
- Тело — блок или один оператор: `while s[n] != 0 n++`.
- **Бесконечный цикл — `while true`.** Отдельного `loop` нет. `while true`
  без `break` внутри компилятор считает бесконечным: после него не нужен
  `return`, а код после него — недостижим (предупреждение).

## 5.7 `for`

```
for имя: T in начало..конец тело
for имя: T in начало...конец тело
for имя: T in начало..конец by шаг тело
for mut имя: T in ... тело
```

- **Тип переменной пишется всегда.** Переменная видна только в теле.
- `a..b` — **полуоткрытый** диапазон: `b` не входит. `a...b` —
  **закрытый**: `b` входит. Записи отличаются одной точкой, поэтому
  основной — полуоткрытый.
- `начало` и `конец` — выражения типа `T` (литералы получают тип `T`).
  **Вычисляются один раз**, до первой итерации, слева направо.
- **Шаг** `by k` — целая константа, не `0`, `|k|` влезает в `T`. Без
  `by` шаг — `1`. Знак задаёт направление, поэтому `by -1` работает и
  для беззнакового `T`.
- **`T`** — целый тип.
- Без `mut` переменная неизменяема в теле. С `mut` её можно менять, и это
  **влияет на ход цикла**, как в C.
- Тело — блок или один оператор. Граница диапазона перед телом — по
  правилам 5.5; правило скобок действует после `in`.

### Семантика

**Цикл не переходит за границу и не переполняет переменную.** Для шага
`k > 0` и полуоткрытого диапазона

```
for mut i: T in a..b by k { тело }
```

работает как

```
let mut i: T = a
let end: T = b
if i < end {
    while true {
        тело
        if i >= end break          // тело (for mut) перепрыгнуло end
        if end - i <= k break      // следующий шаг дошёл бы до end
        i = i + k
    }
}
```

- Для закрытого `a...b`: в первом `if` — `i <= end`, во втором —
  `end - i < k`.
- Для шага вниз (`k < 0`): сравнения зеркальные (`i > end`, `i <= end`,
  …), разность — `i - end`, шаг — `i = i - |k|`.
- Разность всегда неотрицательна и считается в беззнаковом типе той же
  ширины, поэтому не переполняется и у знаковых `T`.
- `continue` в теле переходит к проверкам после тела.

Следствия:

| Цикл | Итерации |
|---|---|
| `for i: UWord in 0..argc` при `argc = 0` | ни одной |
| `for i: UByte in 0...0xFF` | 256, без зацикливания |
| `for i: UWord in 0...9 by 2` | 0, 2, 4, 6, 8 |
| `for i: UWord in 10...0 by -1` | 10, 9, …, 0 |
| `for i: UByte in 0xFF...0 by -3` | 0xFF, 0xFC, …, 0x00, без ухода в 0xFD |
| `for i: UWord in argc..0 by -1` | argc, …, 1; индекс — `i - 1` |
| `for i: UWord in 5..5` | ни одной |

- **Пустой диапазон** — ноль итераций, не ошибка.
- Если тело `for mut` **переполнило** переменную (`i++` у `UByte` от
  `0xFF` даёт `0`), она снова меньше `end`, и цикл может не
  закончиться. Это ответственность программиста.
- Компилятор может проверять одно условие вместо двух, если видит, что
  переменная не меняется в теле.

Пример: [examples/ranges.m](../../examples/ranges.m),
[examples/loops.m](../../examples/loops.m).

## 5.8 `break` и `continue`

- `break` выходит из ближайшего `while`, `for` или `switch`.
- `continue` переходит к следующей итерации ближайшего `while` или `for`
  (`switch` он пропускает).
- **Меток нет.** Выйти из двух циклов сразу — через флаг или `return`.
- `break` или `continue` вне цикла — ошибка. Граница функции — тоже
  граница: `break` во вложенной функции или литерале не выходит из цикла
  внешней функции.

## 5.9 `switch`

```
switch выражение {
    case константа:
        операторы
    case константа:
    case константа:
        операторы
    default:
        операторы
}
```

- Выражение — целое или `enum`, без скобок, как у `if`. Тело — всегда
  блок `{ }`.
- Метка `case` — константное выражение того же типа. Одинаковые метки —
  ошибка. Не больше одного `default`, в любом месте.
- **Выполнение проваливается** в следующий `case`, пока не встретится
  `break`, `return` или `continue`, как в C.
- **`break` внутри `switch` выходит из `switch`**, а не из цикла вокруг.
  `continue` относится к циклу.
- Полнота не проверяется: если ни одна метка не подошла и `default` нет,
  ничего не выполняется.
- **`let` прямо в `case` — ошибка**, в том числе вложенная функция: в C
  из-за этого можно перепрыгнуть инициализацию. Переменную объявляют в
  блоке:

  ```
  case 0: {
      let half: UWord = n / 2
      return half
  }
  ```

Пример: [examples/switch.m](../../examples/switch.m).

## 5.10 `return`

- `return выражение` — в функции с результатом; тип выражения — тип
  результата.
- `return` — в `Void`-функции. В конце `Void`-функции он не нужен.
- В `Void`-функции `return` никогда не берёт выражение, а в функции с
  результатом — всегда. Поэтому `if done return` и следующая строка
  `x = 1` — два оператора.
- **Функция с результатом не может дойти до `}`.** Компилятор проверяет
  это просто: в теле должен быть оператор, после которого выполнение не
  идёт дальше, — `return`, `while true` без `break`, `if`/`else`, обе
  ветви которого такие, или блок, в котором есть такой оператор. Иначе —
  ошибка. Обычно это последний оператор; если после него есть ещё код,
  этот код недостижим (предупреждение), но ошибки нет.
- Типа «не возвращается» нет: после вызова `panic(...)` в функции с
  результатом всё равно нужен `return`.
- Код после `return`, `break`, `continue` и `while true` без `break` —
  предупреждение.
