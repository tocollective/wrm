# 1. Лексика

[← Оглавление](README.md) · [Типы →](02-types.md)

## 1.1 Исходный текст

- Файл программы на M — текст в UTF-8 с расширением `.m`.
- Символы вне ASCII разрешены в комментариях, строковых и символьных
  литералах (1.6). В идентификаторах — только ASCII.
- Пробельные символы: пробел, табуляция, `CR`, `LF`. Они только
  разделяют токены. Отступы и переводы строки ничего не значат: любую
  конструкцию можно перенести на другую строку, а табы и пробелы можно
  смешивать.
- Точки с запятой нет. Конец оператора определяет грамматика
  ([5.1](05-statements.md#51-операторы-и-их-границы)).

## 1.2 Комментарии

| Запись | Что это |
|---|---|
| `// ...` | до конца строки |
| `/* ... */` | блочный; **вложенный**: `/* a /* b */ c */` — один комментарий |
| `/// ...` | doc-комментарий до конца строки |

- Блочный комментарий можно поставить в любом месте, где допустим
  пробел, в том числе внутри выражения: `greet(/* имя */ "M")`.
  Незакрытый `/*` — ошибка.
- Doc-комментарий описывает объявление, которое идёт сразу за ним:
  функцию, `type`, `enum`, поле структуры, элемент `enum`, глобальную
  переменную. Несколько строк `///` подряд — один комментарий. `///` в
  другом месте — предупреждение.
- `////` и больше косых черт — обычный комментарий.

Пример: [examples/comments.m](../../examples/comments.m).

## 1.3 Идентификаторы

```
identifier = (letter | "_") { letter | digit | "_" }
letter     = "A"…"Z" | "a"…"z"
digit      = "0"…"9"
```

- Регистр различается: `color` и `Color` — разные имена.
- Идентификатор не может совпадать с ключевым словом (1.4), именем
  встроенного типа (1.4) или встроенной функции
  ([7.2](07-hardware.md#72-встроенные-функции)).
- Соглашения (не правила языка): типы — `PascalCase`, функции и
  переменные — `camelCase`, константы — `UPPER_CASE`.

## 1.4 Зарезервированные слова

Ключевые слова:

```
align    as       asm      break    by       case     continue default
else     enum     export   extern   false    for      from     if
import   in       let      mut      null     packed   return   switch
true     type     volatile while
```

Имена встроенных типов (тоже зарезервированы):

```
Byte  UByte  Half  UHalf  Word  UWord  Bool  Float  Void
```

Имена встроенных функций: `mfcr`, `mtcr`, `syscall`, `wfi`, `hlt`,
`tlbi`, `fence`, `breakpoint`, `clz`, `ctz`, `popcount`, `bswap`,
`rotl`, `rotr`, `atomicLoad`, `atomicStore`, `atomicSwap`, `atomicAdd`,
`atomicCompareSwap`, `sizeof`, `alignof`, `offsetof`, `vaCount`, `vaArg`.

## 1.5 Числовые литералы

### Целые

| Запись | Пример |
|---|---|
| десятичная | `0`, `42`, `1_000_000` |
| шестнадцатеричная | `0xFF`, `0xfd00_2000` |
| двоичная | `0b1010_1010` |

- Префиксы пишутся строчными: `0x`, `0b`. Шестнадцатеричные цифры — в
  любом регистре.
- `_` можно ставить **только между цифрами**: `0xFD00_2000` — да,
  `0x_FF`, `1_`, `1__0` — ошибка.
- Восьмеричных литералов нет. Десятичное число с ведущим нулём (`010`) —
  ошибка, чтобы его не прочитали как восьмеричное из C. Сам `0` можно.
- Знака у литерала нет: `-1` — это унарный минус и литерал `1`
  ([4.5](04-expressions.md#45-унарные-операторы)).
- Тип целому литералу задаёт контекст
  ([4.2](04-expressions.md#42-литералы-и-константные-выражения)).

### С плавающей точкой

```
float_literal = digits "." digits
```

- Цифры обязательны **с обеих сторон** точки: `1.5`, `0.5`, `2.0`.
  `1.`, `.5`, `1e10` — не литералы.
- Тип — `Float`.

Точка после числа начинает дробную часть, только если за ней идёт
цифра. Поэтому `0..argc` — это `0`, `..`, `argc`, а не `0.` и `.argc`.

## 1.6 Символьные и строковые литералы

- **Символ** — ровно один Unicode-код. ASCII и экранированные байты,
  например `'a'` и `'\xE9'`, имеют тип `UByte`. Символы вне ASCII,
  записанные напрямую, имеют тип `UWord`: `'д'` — `0x0434`, `'é'` —
  `0x00E9`, `'😀'` — `0x1F600`. Значение — код символа, не байты UTF-8.
- **Строка** `"..."` — байты UTF-8 с завершающим нулём, тип `*UByte`
  ([2.4](02-types.md#24-указатели)).
- В строке разрешены символы Unicode; они кодируются в UTF-8:
  `"café"` содержит байты `63 61 66 C3 A9 00`. Индексация через `*UByte`
  обращается к байтам, а не к символам Unicode.
- Символьный литерал не может содержать несколько Unicode-кодов:
  `'ab'`, `'é'` (буква и комбинируемый акцент), `'👩‍💻'` — ошибки.
- `\` и кавычку, закрывающую литерал, нужно экранировать. Табуляция,
  перевод строки и управляющие символы ASCII внутри литерала — ошибка;
  используйте экранирование.
- `\xNN` вставляет один байт без перекодирования, поэтому строка может
  содержать произвольные байты, в том числе некорректный UTF-8.
  Пути импортов и строки внутри `asm` должны содержать корректный UTF-8.
  Вывод UTF-8 зависит от устройства: шрифт видеокарты — Windows-1252.

| Экранирование | Байт |
|---|---|
| `\n` | `0x0A` |
| `\r` | `0x0D` |
| `\t` | `0x09` |
| `\0` | `0x00` |
| `\\` | `0x5C` |
| `\'` | `0x27` |
| `\"` | `0x22` |
| `\xNN` | `0xNN`, ровно две шестнадцатеричные цифры |

Другие последовательности (`\a`, `\u…`, `\x1`) — ошибка.

Пример: [examples/literals.m](../../examples/literals.m).

## 1.7 Прочие литералы

- `true`, `false` — значения типа `Bool`.
- `null` — нулевой указатель любого типа указателя и типа функции.

## 1.8 Операторы и разделители

```
+   -   *   /   %   +|  -|  *|
&   |   ^   ~   <<  >>
==  !=  <   <=  >   >=
&&  ||  !
=   +=  -=  *=  /=  %=  &=  |=  ^=  <<=  >>=
++  --
.   ..  ...
,   :   (   )   [   ]   {   }
```

- Лексер берёт самый длинный подходящий токен: `...` раньше `..`, `..`
  раньше `.`, `<<=` раньше `<<`, `+|` раньше `+`.
- `&mut` — это два токена, `&` и `mut`.
