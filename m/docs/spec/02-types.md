# 2. Типы

[← Лексика](01-lexical.md) · [Оглавление](README.md) · [Объявления →](03-declarations.md)

## 2.1 Обзор

| Категория | Типы |
|---|---|
| Целые | `Byte`, `UByte`, `Half`, `UHalf`, `Word`, `UWord` |
| Логический | `Bool` |
| С плавающей точкой | `Float` |
| Пустой | `Void` (только тип результата и `*Void`) |
| Указатели | `*T`, `*mut T`, `*volatile T`, `*volatile mut T`; `*Void` — на что угодно |
| Массивы | `T[N]`; в `let` с литералом — `T[]`; в параметре — `T[]`, `mut T[]` |
| Структуры | `type Name { ... }`, `packed type Name { ... }` |
| Перечисления | `enum Name: Base { ... }` |
| Функции | `(a: A, b: B): R` |
| Псевдонимы | `type Name = T` |

Вывода типов нет: тип каждой переменной, параметра и результата пишется
явно ([3.2](03-declarations.md#32-переменные)).

## 2.2 Скалярные типы

| M | C (ABI.md) | Размер / выравнивание | Диапазон |
|---|---|---|---|
| `Byte` | `signed char` | 1 / 1 | −128 … 127 |
| `UByte` | `unsigned char` | 1 / 1 | 0 … 255 |
| `Half` | `short` | 2 / 2 | −32 768 … 32 767 |
| `UHalf` | `unsigned short` | 2 / 2 | 0 … 65 535 |
| `Word` | `int` | 4 / 4 | −2³¹ … 2³¹−1 |
| `UWord` | `unsigned int` | 4 / 4 | 0 … 2³²−1 |
| `Bool` | `_Bool` | 1 / 1 | `false` = 0, `true` = 1 |
| `Float` | `float` | 4 / 4 | IEEE 754 binary32 |

- Знаковые целые — в дополнительном коде.
- **64-битных типов нет**: процессор 32-битный. 64-битные значения
  (счётчики `CYCLE`/`CYCLEH`) хранятся как пара `UWord`. C-функции с
  `long long` или `double` в сигнатуре через `extern` не вызвать.
- `UWord` — это и `size_t`, и `uintptr_t`: указатель тоже 4 байта.
- `Float` живёт в регистрах общего назначения, операции — инструкции
  `FADD`…`UTOF`. Без ловушек: недопустимая операция даёт NaN,
  переполнение и деление на ноль — ±∞ (INSTRUCTIONS, «Floating point»).
  `Float` можно реализовать после целых, но имя зарезервировано сразу.
- `Void` пишется только как тип результата функции (в том числе в типе
  функции) и как указуемый тип указателя: `*Void`
  ([2.4](#24-указатели)). Переменных, параметров, полей и массивов типа
  `Void` нет.

## 2.3 Изменяемость

Изменяемость принадлежит **переменной**, а не типу: `let x` нельзя
менять, `let mut x` — можно, со всеми полями и элементами. У полей
структуры `mut` не пишется.

Единственное место, где изменяемость — часть типа, — указатель
(2.4): `*T` и `*mut T` — разные типы.

## 2.4 Указатели

| Тип | Читать через указатель | Писать через указатель |
|---|---|---|
| `*T` | да | нет |
| `*mut T` | да | да |
| `*volatile T` | да, как обращение к устройству | нет |
| `*volatile mut T` | да, как обращение к устройству | да, как обращение к устройству |

- Размер и выравнивание — 4 / 4.
- Любой указатель может быть нулевым: `null` подходит к любому типу
  указателя. Отдельного «ненулевого» указателя нет. Разыменование `null`
  — page fault: ядро держит первые 8KB неотображёнными (ABI, «Entering
  the kernel»).
- Изменяемость переменной и указуемого независимы:

  | Объявление | Переставить `p` | Писать через `p` |
  |---|---|---|
  | `let p: *T` | нет | нет |
  | `let mut p: *T` | да | нет |
  | `let p: *mut T` | нет | да |
  | `let mut p: *mut T` | да | да |

- Строковый литерал имеет тип `*UByte`: записать в него нельзя.
- Арифметики указателей нет. Адрес элемента — `&p[i]`
  ([4.4](04-expressions.md#44-постфиксные-операторы)).
- Что делает `volatile` — [7.1](07-hardware.md#71-volatile-и-mmio).

### `*Void`

Указатель на данные неизвестного типа, как `void *` в C:

```
type Visit = (item: *Item, ctx: *mut Void): Void

let forEach(first: *Item, visit: Visit, ctx: *mut Void): Void { ... }

let totalSize(first: *Item): UWord {
    let mut total: UWord = 0
    forEach(first, (item: *Item, ctx: *mut Void): Void {
        let sum: *mut UWord = ctx as *mut UWord
        sum[0] += item.size             // not "*sum": it would continue the line above (5.1)
    }, &mut total)                  // *mut UWord → *mut Void неявно
    return total
}
```

- Бывает всех четырёх видов: `*Void`, `*mut Void`, `*volatile Void`,
  `*volatile mut Void`. Размер и выравнивание — 4 / 4.
- **Любой указатель неявно становится `*Void`** того же вида; `mut` при
  этом можно снять, `volatile` — добавить
  ([2.10](#210-совместимость-и-неявные-приведения)). Тип указуемого
  теряется, прав не прибавляется. **Обратно — только `as`**: тип нужно
  назвать явно, `ctx as *mut UWord`.
- **Через `*Void` нельзя ни читать, ни писать:** у `Void` нет размера и
  полей, поэтому `*p`, `p[i]` и `p.f` — ошибки. Сначала `as *T`.
- `==`, `!=`, `null`, `as UWord` и `UWord as *Void` — как у любого
  указателя.
- Неявное приведение — только на один уровень, как в C: `**T` (то есть
  `*(*T)`) становится `*Void`, но не `**Void`.
- Массив сам в `*Void` не превращается, даже в аргументе: пишут `&buf`
  или `&buf[0]`.
- Типы функций совпадают только точно:
  `(p: *UByte): Void` и `(p: *Void): Void` — разные типы.
- Функция приводится к `*Void` и обратно через `as`
  ([4.6](04-expressions.md#46-приведение-as)).

Пример: [examples/void.m](../../examples/void.m).

## 2.5 Массивы

- **`T[N]` — значение** из `N` элементов типа `T`, без отступов между
  ними. Копируется при присваивании, передаче и возврате целиком.
  `N` — константное выражение
  ([4.2](04-expressions.md#42-литералы-и-константные-выражения)),
  не меньше 1. Размер — `N × sizeof(T)`, выравнивание — как у `T`.
- **`T[]` в `let` с литералом массива — `T[N]`**, где `N` — число
  элементов литерала: `let bar: StringPtr[] = ["one", "two"]` — то же,
  что `StringPtr[2]` (3.2). Без литерала — ошибка.
- **`T[]` и `mut T[]` в типе параметра** — указатель
  на первый элемент: `T[]` — тот же тип, что `*T`, `mut T[]` — тот же,
  что `*mut T`. Длина передаётся отдельно. Слово `mut` перед типом
  допустимо только здесь.
- **Массив в параметр `T[]`/`mut T[]`** передаётся как указатель на
  первый элемент, как в C: `fill(buf, 16)`. В `mut T[]` можно передать
  только массив, к которому можно взять `&mut` (3.2). В остальных местах
  массив остаётся значением.
- Срезов и `.len` нет. Проверки границ нет.

### Как читать тип

`[N]` и `[]` относятся ко **всему типу слева**:

| Запись | Что это |
|---|---|
| `*UByte[4]` | массив из 4 указателей на `UByte` |
| `*(UByte[4])` | указатель на массив из 4 `UByte` |
| `*UByte[]` (в параметре) | указатель на первый из указателей — `argv` |
| `UWord[4][8]` | массив из 8 массивов по 4 `UWord` |

Круглые скобки в типе только группируют.

## 2.6 Структуры

```
type Header {
    kind:   UByte,
    length: UWord,
    flags:  UHalf,
}
```

- Поля разделяются запятыми, последняя запятая необязательна. Нужно хотя
  бы одно поле. Имена полей в структуре уникальны.
- Тип поля — любой, кроме `Void`, `T[]` и самой структуры по значению
  (прямо или через другие структуры и массивы). Через указатель — можно:
  `next: *mut Node`.
- Структуры сравниваются по имени: две структуры с одинаковыми полями —
  разные типы.

### Раскладка

Как в C (ABI, «Data types»):

- поля идут в порядке объявления, компилятор их не переставляет;
- каждое поле выровнено на своё выравнивание, перед ним при
  необходимости вставляется отступ;
- выравнивание структуры — наибольшее выравнивание поля;
- размер — округление конца последнего поля вверх до выравнивания
  структуры.

| `Header` | Смещение | Размер |
|---|---|---|
| `kind` | 0 | 1 |
| отступ | 1 | 3 |
| `length` | 4 | 4 |
| `flags` | 8 | 2 |
| отступ | 10 | 2 |
| **итого** | | **12**, выравнивание 4 |

### `packed type`

```
packed type DiskHeader {
    kind:   UByte,  // смещение 0
    length: UWord,  // смещение 1
    flags:  UHalf,  // смещение 5
}                   // размер 7, выравнивание 1
```

- Отступов нет, выравнивание структуры — 1, размер — сумма размеров
  полей.
- Невыровненное поле компилятор читает и пишет побайтово (`LBU`/`SB` и
  сдвиги): невыровненный `LW`/`SW` на этой машине — исключение
  (`CAUSE` 3/4).
- Взять адрес невыровненного поля (`&h.length`) — ошибка: через такой
  указатель обычный `LW` упадёт. Адрес выровненного поля (`&h.kind`)
  взять можно.

Битовых полей нет: флаги — это константы и операторы `|`, `&`, `<<`.

Пример: [examples/layout.m](../../examples/layout.m).

## 2.7 Перечисления

```
enum Key: UByte {
    None,          // 0
    Escape,        // 1
    F1 = 0x70,     // 0x70
    F2,            // 0x71
}
```

- Базовый тип — целый (`Byte` … `UWord`). Размер и выравнивание — как у
  него.
- Элемент без `=` равен предыдущему плюс 1, первый — 0. Значение после
  `=` — константное выражение; от него счёт продолжается.
- Ошибки: значение не влезает в базовый тип (в том числе полученное
  автоматически: `A = 255, B` у `UByte`); два элемента с одинаковым
  значением; два элемента с одинаковым именем.
- Элемент пишется с именем типа: `Key.Escape`. Без имени типа
  (`Escape`) — ошибка.
- В базовый тип и обратно — только через `as`. Обратное приведение не
  проверяется: в переменной `Key` может оказаться значение, которого нет
  в списке.
- Значения `enum` сравниваются `==`, `!=`, `<`, `<=`, `>`, `>=` (как
  базовый тип). Арифметики над ними нет.

Пример: [examples/enums.m](../../examples/enums.m).

## 2.8 Тип функции

```
(a: Word, b: Word): Word
(): Void
```

- Запись — сигнатура без имени функции, **с именами параметров**. Имена
  служат документацией и на тип не влияют: `(x: Word, y: Word): Word` и
  `(a: Word, b: Word): Word` — один тип.
- Значение — указатель на код, 4 / 4, как указатель на функцию в C. Его
  можно передать в `extern`-функцию и получить из ассемблера.
- Может быть `null`. Вызов `null` — page fault при выборке инструкции.
- Имя функции — уже значение этого типа, без `&`: `let f: Action = foo`.
- Тип результата в записи — это весь тип после `:`: `(): UByte[4]` —
  функция, возвращающая массив. Массив функций пишется со скобками
  `((): Void)[4]` или через псевдоним.
- Значение этого типа дают имя функции (в том числе вложенной), функция,
  объявленная через `let mut`, и литерал функции
  ([3.8](03-declarations.md#38-вложенные-функции-и-литералы)).

Последний параметр `args: ...` делает тип функции вариативным. Этот
маркер учитывается при сравнении типов; правила пакета и чтения аргументов —
в [3.4](03-declarations.md#вариативные-параметры).

Пример: [examples/functions.m](../../examples/functions.m).

## 2.9 Псевдонимы

```
type OpFunc = (left: Word, right: Word): Word
type Uart   = *volatile mut UartRegs
```

- Псевдоним — другое имя того же типа: `as` между ними не нужен.
- Объявляется только на верхнем уровне. Псевдоним, который ссылается на
  себя (`type A = *A`), — ошибка. `packed` у псевдонима — ошибка.
- «Нового типа», несовместимого с исходным, нет.

## 2.10 Совместимость и неявные приведения

Два типа совпадают, если:

- это одна и та же структура или один `enum` (по объявлению);
- это скаляры с одним именем;
- это указатели с одинаковыми `volatile`, `mut` и совпадающими
  указуемыми типами;
- это массивы одной длины с совпадающими типами элементов;
- это типы функций с совпадающими типами параметров (по порядку) и
  результата;
- один из них — псевдоним другого.

Неявных приведений нет, кроме пяти. Все они только отнимают права
или ничего не меняют в представлении:

| Откуда | Куда | Где |
|---|---|---|
| литерал | любой подходящий тип | везде, где тип известен ([4.2](04-expressions.md#42-литералы-и-константные-выражения)) |
| `*mut T` | `*T` | везде |
| `*T`, `*mut T` | `*volatile T`, `*volatile mut T` (с тем же `mut` или без) | везде |
| любой указатель | `*Void` того же вида; `mut` можно снять, `volatile` — добавить ([2.4](#24-указатели)) | везде |
| `T[N]` | `T[]`, `mut T[]` | только аргумент вызова |

Всё остальное — через `as`
([4.6](04-expressions.md#46-приведение-as)).

## 2.11 Размеры для `sizeof` и ABI

| Тип | `sizeof` | `alignof` | Передача по ABI |
|---|---|---|---|
| целые, `Bool`, `Float`, указатели, функции, `enum` | 1/2/4 | = размеру | один регистр; 8- и 16-битные расширяет вызывающий: знаковые — по знаку, беззнаковые — нулями |
| структура, массив до 8 байт | по раскладке | по раскладке | в регистрах |
| структура, массив больше 8 байт | по раскладке | по раскладке | по адресу копии; возврат — через скрытый первый аргумент (ABI, «Arguments», «Return values») |
