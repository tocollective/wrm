# 6. Модули

[← Операторы](05-statements.md) · [Оглавление](README.md) · [Железо →](07-hardware.md)

## 6.1 Файл — модуль

- Каждый файл `.m` — отдельный модуль и отдельная единица компиляции:
  один файл — один объектный ELF-файл (ABI.md), см.
  [COMPILER.md](../COMPILER.md).
- **Всё, что объявлено в файле, по умолчанию локально.** Наружу видно
  только то, что перечислено в `export`.
- Пакетов, пространств имён и вложенных модулей нет.

## 6.2 `export`

```
export { colorRed, colorGreen }
export { Color }
export { colorMix as mix }
```

- **Экспорт только явный, по именам.** Экспорта «всего сразу» нет.
- `export { }` можно писать **в любом месте файла и сколько угодно
  раз**: в начале как оглавление, рядом с объявлением или в конце.
- Экспортировать можно функции, глобальные переменные (в том числе
  переменные-функции `let mut f(...)`), структуры, псевдонимы, `enum` и
  `extern`-объявления. Локальные переменные и вложенные функции — нет.
- **`as`** экспортирует под другим именем: импортирующие видят `mix`, а
  не `colorMix`. Одно имя можно экспортировать под несколькими именами.
- **`main` экспортируется сама**, `export { main }` не нужен (но и не
  ошибка). `crt0` ищет глобальный символ `main`.
- Ошибки: экспорт имени, которого нет в файле; два экспорта с одним
  внешним именем; экспорт импортированного имени (реэкспорта нет).

### `extern` и экспорт

```
// externs.m
extern let puts(msg: *UByte): Void
export { puts }
```

Экспорт `extern`-объявления отдаёт **объявление**: файл, который
импортирует `puts`, может её вызвать, а сам символ определяет кто-то
третий (здесь — ассемблер). Это способ собрать объявления ассемблерных
функций в одном файле.

## 6.3 `import`

```
import { puts } from "externs.m"
import { Color, colorRed, mix } from "color.m"
import { colorGreen as green } from "color.m"
```

- **Импорт только по именам**, без `import *`.
- Один и тот же файл можно импортировать несколько раз.
- **`as`** меняет имя только внутри этого файла; символ ELF остаётся
  прежним.
- Импортированное имя становится именем верхнего уровня файла. Совпадение
  с другим именем верхнего уровня (своим или импортированным) — ошибка.
- `import` можно писать в любом месте верхнего уровня, но обычно его
  ставят в начало.
- Ошибки: файл не найден; имя не экспортировано из этого файла.
- Неиспользуемое импортированное имя — предупреждение.
- Циклический импорт (`a.m` импортирует `b.m`, `b.m` — `a.m`)
  разрешён: порядок объявлений не важен
  ([3.7](03-declarations.md#37-область-видимости-и-порядок)).

### Где ищется файл

1. Относительно каталога **текущего** файла: `"color.m"`,
   `"../externs.m"`, `"drivers/uart.m"`.
2. Затем по очереди в каталогах, переданных компилятору флагом `-I`, как
   `-I` у `cc` для `#include`:

   ```
   m -I /opt/m/lib main.m
   ```

   ```
   import { memcpy } from "rt/mem.m"     // найдётся как /opt/m/lib/rt/mem.m
   ```

Берётся первый найденный файл.

## 6.4 Символы ELF

| Имя | Символ |
|---|---|
| экспортированная функция или переменная | глобальный (`STB_GLOBAL`), имя — внешнее имя из `export` |
| `main` | глобальный `main` |
| неэкспортированная функция или переменная | локальный (`STB_LOCAL`): не конфликтует с такими же именами в других файлах |
| вложенная функция, литерал функции, тело переменной-функции | всегда локальный; имя выбирает компилятор ([COMPILER.md](../COMPILER.md)) |
| `extern`-объявление | неопределённый глобальный символ с именем из объявления |
| тип, псевдоним, `enum` | символа нет |

- Пространства имён модулей в символах нет, как в C. Если две
  экспортированные `mix` из разных файлов попали в одну программу — это
  ошибка линкера; одну переименовывают через `export { ... as ... }`.
- Нет `main` или их две — ошибка линкера.

Пример: [examples/modules/](../../examples/modules/),
[examples/externs.m](../../examples/externs.m).
