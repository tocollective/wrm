## 7.1 `volatile` и MMIO

Регистры устройств лежат в памяти (I/O-область `0xFD000000`–`0xFDFFFFFF`,
по странице на устройство), и у обращений к ним есть побочные эффекты:
чтение `DATA` у UART снимает байт из FIFO, чтение `STATUS` сбрасывает бит
переполнения. Для них есть
квалификатор указателя:

```
type UartRegs {
    data:    UWord,
    status:  UWord,
    control: UWord,
}

let uart: *volatile mut UartRegs = 0xFD00_2000 as *volatile mut UartRegs

let putc(c: UByte): Void {
    while uart.status & UART_TX_READY == 0 {}
    uart.data = c as UWord
}
```

- `volatile` бывает **только у указателя**: `*volatile T` (только
  чтение), `*volatile mut T` (чтение и запись). Переменных `volatile`
  нет: данные, общие с обработчиком прерываний, защищают атомики (7.5).
- **Каждое чтение и запись через такой указатель выполняется ровно один
  раз, в порядке исходного текста, той ширины, что у типа** (`UByte` —
  `LBU`/`SB`, `UHalf` — `LHU`/`SH`, `UWord` — `LW`/`SW`). Компилятор не
  выбрасывает, не объединяет, не дублирует и не переставляет их между
  собой и не выносит из циклов.
- Квалификатор проходит через `.`, `[]` и `&`: `&uart.status` — это
  `*volatile UWord`.
- Копия структуры целиком (`let s: UartRegs = *uart`) читает поля по
  одному, в порядке объявления, каждое своей ширины. Запись структуры
  целиком — так же.
- `volatile` **добавляется неявно** (`*mut T` → `*volatile mut T`), а
  **снимается только через `as`**. Поэтому функцию с параметром
  `*volatile mut UByte` можно вызвать и для обычной памяти.
- Обычные обращения к памяти компилятор может переставлять относительно
  `volatile`-обращений. Чтобы упорядочить их (например, для DMA), есть
  `fence()`.

Пример: [examples/mmio.m](../../examples/mmio.m).

## 7.2 Встроенные функции

Встроенные функции вызываются как обычные, но их имена зарезервированы:
объявить свою функцию, переменную или параметр с таким именем нельзя.
Взять их адрес (`let f: ... = wfi`) нельзя.

| Функция | Инструкция | Тип |
|---|---|---|
| `mfcr(N)` | `MFCR rd, N` | `UWord` |
| `mtcr(N, x)` | `MTCR N, rx` | `Void`; `x: UWord` |
| `syscall(n, a1, …, a6)` | `SYSCALL` | `Word` |
| `wfi()` | `WFI` | `Void` |
| `hlt()` | `HLT` | `Void` |
| `tlbi(addr)`, `tlbi(x, mode)` | `TLBI` | `Void`; `addr`, `x: UWord`; `mode` — константа 0–2 |
| `fence()` | `FENCE` | `Void` |
| `breakpoint()` | `BREAK` | `Void` |
| `clz(x)`, `ctz(x)`, `popcount(x)` | `CLZ`, `CTZ`, `POPCNT` | `UWord`; `x: Word` или `UWord` |
| `bswap(x)` | `BSWAP` | тип `x`; `x: Word` или `UWord` |
| `rotl(x, n)`, `rotr(x, n)` | `ROL`, `ROR` | тип `x`; `x: Word` или `UWord`, `n: UWord` |
| `sizeof(T)` | — | `UWord`, константа |
| `alignof(T)` | — | `UWord`, константа |
| `offsetof(T, поле)` | — | `UWord`, константа |
| `vaCount(args)` | загрузка длины пакета | `UWord`; вариативный параметр |
| `vaArg(args, i, T)` | загрузка слова и нормализация | `T`; скалярный тип, `i: UWord`; [3.4](03-declarations.md#вариативные-параметры) |
| атомики | цикл `LL`/`SC` | 7.5 |

### Управляющие регистры

- `N` у `mfcr`/`mtcr` — **константное выражение**: номер регистра
  кодируется в `imm14` инструкции. Переменная — ошибка.
- Номера (INSTRUCTIONS, «Control registers»): `STATUS` 0, `EPC` 1,
  `IVEC` 2, `SCRATCH` 3, `CAUSE` 4, `BADADDR` 5, `PTBR` 6, `CYCLE` 7,
  `CYCLEH` 8, `INSTRET` 9, `INSTRETH` 10, `CPUID` 11, `TADDR0` 12,
  `TCTRL0` 13, `TADDR1` 14, `TCTRL1` 15, `HARTID` 16, `FCSR` 17. Язык
  имён не вводит: их объявляют константами. Другой номер — ошибка.
- `FCSR` (флаги исключений и режим округления `Float`) доступен и в
  user mode: `mfcr(17)` читает флаги, `mtcr(17, x)` сбрасывает их или
  меняет режим. Компилятор не переставляет операции с `Float` через
  `mtcr(17, ...)` и `mfcr(17)`. Константные выражения с `Float`
  вычисляются при компиляции: всегда к ближайшему и без флагов.

### Битовые операции

- `clz(x)` — число нулей перед старшей единицей, `ctz(x)` — после
  младшей; для `0` обе дают 32. `popcount(x)` — число единиц.
- `bswap(x)` — байты в обратном порядке (смена порядка байт в сети).
- `rotl(x, n)`, `rotr(x, n)` — циклический сдвиг влево и вправо на
  `n & 31` бит.
- Литерал в `x` получает тип `UWord`. Для `Byte` и `Half` нужно `as`.
- `mtcr` не переставляется с обращениями к памяти: после `mtcr(PTBR, ...)`
  следующие обращения уже идут через новую таблицу страниц.

### `tlbi`

- `tlbi(addr)` — `TLBI addr`: сбросить трансляцию страницы `addr`.
- `tlbi(x, mode)` — `mode` — **константное выражение** 0–2, оно
  кодируется в `imm14` (INSTRUCTIONS, «TLB»): 0 — как `tlbi(x)`;
  1 — `TLBI.ASID`, сбросить все неглобальные записи ASID `x & 0xFF`;
  2 — `TLBI.ALL`, сбросить весь TLB, `x` вычисляется, но не используется.
  Другой `mode` — ошибка.

### `syscall`

- `n` — номер вызова, кладётся в `r9`. `a1`…`a6` — от 0 до 6 аргументов,
  в `r1`–`r6` (ABI, «System calls»).
- Каждый аргумент и `n` — `Word`, `UWord` или указатель. Литералы
  получают тип `UWord`.
- Результат — `Word` из `r1`; ошибка — отрицательное значение от −4095
  до −1 (`-errno`).
- Ядро сохраняет всё, кроме `r1` и `r2`.

### `sizeof`, `alignof`, `offsetof`

- Аргумент — тип, а не выражение.
- `offsetof(T, поле)` — только прямое поле структуры `T`.
- `sizeof` у `Void` и `T[]` — ошибка.

Пример: [examples/cpu.m](../../examples/cpu.m),
[examples/layout.m](../../examples/layout.m).

## 7.3 Порядок обращений к памяти

Машина одноядерная и выполняет обращения к памяти по порядку. Порядок,
который видит программа, может нарушить только компилятор. Он сохраняет:

- порядок `volatile`-обращений между собой (7.1);
- порядок атомиков относительно всех обращений к памяти (7.5);
- порядок `mtcr`, `tlbi`, `fence`, `syscall`, `asm` и вызовов функций
  относительно всех обращений к памяти.

## 7.4 `asm`

```
asm {
    "fence"
    "hlt"
}
```

- Одна или несколько строк, каждая — строка ассемблера для `tools/asm.py`.
  Компилятор копирует их в вывод как есть.
- **Операндов нет.** Компилятор обращается со вставкой как с вызовом
  неизвестной функции: считает, что она меняет память и все
  caller-saved регистры (`r1`–`r9`, `r31`), и ничего не держит в них
  через вставку.
- Вставка не должна менять `sp`, callee-saved регистры и не должна
  передавать управление за свои пределы.
- Всё, что требует операндов, пишется функцией на ассемблере и
  объявляется через `extern` ([3.5](03-declarations.md#35-extern)).

## 7.5 Атомики

| Функция | Что делает | Результат |
|---|---|---|
| `atomicLoad(p)` | читает `*p` | значение |
| `atomicStore(p, v)` | пишет `v` в `*p` | `Void` |
| `atomicSwap(p, v)` | пишет `v` | старое значение |
| `atomicAdd(p, v)` | прибавляет `v`, с переносом | старое значение |
| `atomicCompareSwap(p, expected, v)` | пишет `v`, только если `*p == expected` | старое значение; запись была, если оно равно `expected` |

- Тип значения `T` — `Word`, `UWord` или указатель. Для других типов —
  ошибка. `atomicAdd` — только `Word` и `UWord`.
- `p` — `*mut T` (у `atomicLoad` достаточно `*T`). Адрес выровнен на 4,
  иначе исключение, как у `LL`.
- Компилятор разворачивает атомик в цикл `LL`/`SC` (INSTRUCTIONS,
  «Atomic word operations»). `atomicLoad`/`atomicStore` на одноядерной
  машине — обычные `LW`/`SW`, но с порядком из 7.3.
- Атомики нужны и на одноядерной машине: между чтением и записью может
  прийти прерывание.
- Атомики на регистрах устройств не использовать: у них свои побочные
  эффекты (INSTRUCTIONS).

```
let acquire(l: *mut UWord): Void {
    while atomicSwap(l, 1) != 0 {}
}

let release(l: *mut UWord): Void {
    atomicStore(l, 0)
}
```

## 7.7 Рантайм

Язык ничего не знает о точке входа и ничего не выполняет до `main`.
Это делает рантайм на ассемблере.

- **Процесс.** `crt0` разбирает блок процесса (`argc`, `argv`, `envp`,
  auxv — ABI, «Process start»), вызывает
  `main(argc: UWord, argv: *UByte[]): Word` и передаёт результат в
  `exit`.
- **Boot-образ.** Свой `crt0`: при входе `r1` — адрес boot info block,
  `.bss` не обнулён, `ra` = 0 (SPECIFICATION, «State at the entry
  point»). Он обнуляет `.bss`, вызывает `main(0, null)` и пишет её
  результат в регистр `OFF` контроллера питания: машина выключается, а
  эмулятор выходит с этим кодом. Пока ОС нет, все программы на M — такие
  образы ([COMPILER.md](../COMPILER.md)).
- **Прерывания и исключения.** Вход в обработчик пишется на ассемблере:
  он стартует без свободных регистров и не может доверять `sp` (ABI,
  «Entering the kernel»). Он сохраняет регистры в кадр, вызывает функцию
  M, например `trap(frame: *mut TrapFrame): Void`, восстанавливает
  регистры и делает `IRET`.
- **`memcpy`, `memset`.** Компилятор вызывает их для копирования и
  обнуления больших структур и массивов, поэтому рантайм (и ядро без
  libc) должен их предоставить (ABI, «Runtime functions»).

## 7.8 Ограничения кодогенерации

Это не правила языка, а то, что компилятор обязан учитывать:

- `imm14` — это ±8KB: кадр стека больше 8KB и смещения дальше 8KB
  адресуются через `r9`, константы вне ±8KB — через `LUI` + `ORI`
  (ABI, «Stack»).
- Условный переход достаёт на ±32KB, дальше — инвертированный переход и
  `JAL`. `JAL` — ±1MB, дальше — veneer'ы линкера через `r9`, поэтому
  `r9` не держат живым через вызов (ABI, «Linker veneers»).
- `sp` выровнен на 8 при каждом вызове, red zone нет.
- Значения `UByte`/`UHalf` в регистрах держатся расширенными нулями,
  `Byte`/`Half` — по знаку. Тогда расширение через `as` бесплатное, а
  после `+`, `-`, `*`, `<<` нужно маскирование.
