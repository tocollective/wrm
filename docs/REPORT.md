# WRM.081632: чего не хватает до полноценной машины

Отчёт по состоянию рабочей копии на 2026-10-01 (ветка `master`, включая
незакоммиченные `mmu.c`, `firmware/demos/*`). Цель — понять, что нужно,
чтобы на машине можно было запустить настоящую ОС (ядро с процессами,
файловой системой и вводом-выводом), а эмулятором было удобно пользоваться
и отлаживать программы.

## Что уже есть

- **CPU:** 32-битный RISC, 32 GPR, классический 5-стадийный конвейер с
  forwarding, load-use stall, предсказанием «не перейдёт», точными
  исключениями и прерываниями.
- **Режимы:** supervisor/user, `SYSCALL`, `IRET`, 11 control-регистров,
  14 кодов `CAUSE` (включая прерывание и `BREAK`).
- **MMU:** двухуровневые таблицы, страницы 4KB и суперстраницы 4MB, права
  R/W/X/U, биты A/D/G, 8-битный ASID в `PTBR`, полностью ассоциативный TLB
  на 64 записи и `TLBI`.
- **Шина и память:** до 4 слотов RAM, ROM на 32MB, I/O-регион по странице
  на устройство.
- **Устройства:** PIC (32 линии, уровневые), клавиатура (HID usage ID, FIFO),
  UART (stdout/stdin хоста); позже добавлены таймер, power-контроллер и
  два дисковых контроллера с DMA.
- **Тактирование:** 48 MHz, привязано к хостовому времени.
- **Инструменты:** ассемблер на Python (выражения, локальные метки,
  псевдоинструкции, `.include`/`.incbin`, листинг).
- **Прошивка:** демо, которое прогоняет все группы инструкций, прерывания,
  MMU и user mode.
- **Сборка:** нативная через SDL3 и веб через Emscripten.

Ядро процессора проработано хорошо. Основные пробелы — в периферии, в
нескольких архитектурных деталях, без которых ОС будет неудобно или
невозможно писать, и в инструментах.

## 1. Критично для запуска ОС

### 1.1 Таймер и счётчики — сделано

- ~~**Программируемый таймер**~~ — сделано: `0xFD003000`, IRQ 2,
  64-битный `COUNT`, `RELOAD`, `VALUE`, `CONTROL` (однократный или
  периодический режим) и `STATUS` со сбросом прерывания.
- ~~**Регистры CPU** `CYCLE`/`CYCLEH` и `INSTRET`/`INSTRETH`~~ — сделано:
  доступны для чтения через `MFCR`, в том числе из user mode.
- **RTC** (дата и время хоста) — желательно, но не срочно.

Устройства тактируются в `motherboard_tick`: каждый такт обновляются таймер
и дисковые контроллеры перед выполнением такта CPU
([source/motherboard.c](../source/motherboard.c)).

### 1.2 Внешняя память — загрузить ОС неоткуда

В `config_t` уже есть `hdd_path[2]` и `floppy_path`, но они нигде не
используются. Весь код должен помещаться в ROM.

Предлагается **блочное устройство** (контроллер диска): регистры `SECTOR`,
`COUNT`, `BUFFER_ADDR` (физический адрес в RAM), `COMMAND` (read/write),
`STATUS` (busy/error/present), размер диска в секторах, IRQ по завершении.
Работать напрямую с RAM (DMA) проще и быстрее, чем через побайтовый порт
данных. Образ диска — обычный файл хоста (`hdd0.img`).

Ещё нужно описать **протокол загрузки**: ROM читает сектор 0 по
фиксированному адресу в RAM и прыгает туда (или грузит ELF). Это отдельный
раздел в `SPECIFICATION.md`.

**Исправлено.** Добавлены два дисковых контроллера: диск 0 на
`0xFD005000` (IRQ 3) и диск 1 на `0xFD006000` (IRQ 4), образы задаются
через `--hdd PATH` (до двух раз). Регистры: `STATUS` (present, read-only,
busy, done, error), `SECTORS`, `SECTOR`, `COUNT`, `ADDRESS`, `COMMAND`
(read/write), `ERROR` (код причины). Передача идёт по DMA прямо в RAM,
по слову за такт, то есть 128 тактов на сектор. `SECTOR`, `COUNT` и
`ADDRESS` сдвигаются по ходу передачи, поэтому после ошибки видно, где
она остановилась, а для чтения дальше достаточно записать новые `COUNT`
и `COMMAND`. Линия IRQ поднята, пока установлен `DONE`. DMA достаёт только
до RAM: ROM и I/O-регион дают ошибку 4. Образ, который хост не может
записать, подключается read-only. Код: `source/devices/disk.c`.

Протокол загрузки описан в `SPECIFICATION.md#boot-protocol`. Образ
начинается с заголовка (`WRMB`, число секторов, смещение точки входа,
флаги) и грузится целиком по адресу `0x00010000`. Точка входа получает
`r1` = блок boot info по `0x00001000`: размер RAM, контроллер и размер
загрузочного диска, адрес и размер образа, частоту. Кроме того,
`r30` = `0x00010000`, supervisor, `STATUS = EXL`, MMU выключен. Прошивка
реализует протокол в `firmware/boot.asm`. Размер RAM она определяет
пробами по границам 1MB, перехватывая load bus error. Если загрузочного
образа нет, прошивка запускает демо. Пример образа —
`firmware/disk/hello.asm`. Тесты: `tests/disk/` (у `tests/run.py`
появились директивы `; @hdd` и `; @args`).

### 1.3 Исключения в supervisor при `IE = 0` останавливают CPU

Сейчас любое исключение в supervisor mode с `IE = 0` делает halt
([cpu.c `cpu_stage_wb`](../source/cpu.c)). При этом обработчик входит именно
с `IE = 0`. Отсюда следствия:

- **Syscall и user-память.** Обработчик `SYSCALL`, который читает аргументы
  из user-памяти (аналог `copy_from_user`), остановит машину на первом же
  page fault. Demand paging и copy-on-write из syscall'ов невозможны, если
  ядро не включает `IE` вручную.
- **Смешанная семантика `IE`.** Флаг одновременно означает «разрешены
  прерывания» и «исключения можно обработать». Ядро не может запретить
  прерывания на время критической секции и при этом пережить в ней
  page fault.

Как исправить: разделить эти роли. Например, исключение в supervisor
обрабатывается всегда, а halt случается только при исключении внутри
обработчика до сохранения `EPC` (нужен флаг «в обработчике», аналог
`EXL` в MIPS). Другой вариант — отдельный вектор или стек для
double fault.

**Исправлено.** В `STATUS` добавлен бит 4 `EXL` («в обработчике»). Вход в
обработчик ставит `EXL`, `IRET` снимает. Исключение обрабатывается в любом
режиме независимо от `IE`, а halt (double fault) происходит только при
`EXL = 1`. Прерывания принимаются при `IE = 1` и `EXL = 0`. После сброса
`EXL = 1`, поэтому до установки `IVEC` и первой записи в `STATUS` fault,
как и раньше, останавливает CPU. Обработчик, который может сам вызвать
fault, сохраняет `EPC`/`CAUSE`/`BADADDR`/`STATUS` и снимает `EXL`
(см. `INSTRUCTIONS.md#exceptions`).

### 1.4 Атомарные операции — сделано

Выбран один механизм: `LL`/`SC` для 32-битных слов и `FENCE`.
Резервация `LL` привязана к физическому адресу; запись CPU или DMA в это
слово сбрасывает её. `SC` сообщает успех или неудачу через `rd`. Обмен,
fetch-add и compare-and-swap выражаются циклами `LL`/`SC`; отдельных
`AMOSWAP`, `AMOADD` и `CAS` в ISA нет.

### 1.5 MMU: информация для ОС и защита

- ~~**Биты Accessed/Dirty в PTE.**~~ Сделано: MMU выставляет `A` при
  разрешённом доступе и `D` при разрешённой трансляции записи в листовой
  PTE. Неудачный `SC` не выставляет `D`; спекулятивная выборка может
  выставить `A`.
- ~~**ASID и глобальные страницы.**~~ Сделано: `PTBR` содержит 8-битный
  ASID, бит `G` помечает отображение общим для всех ASID. При переключении
  ASID записи TLB сохраняются; `TLBI` удаляет запись текущего ASID и
  соответствующую глобальную запись.
- **Нет запрета supervisor-доступа к user-страницам** (аналог SUM/SMAP в
  RISC-V). Не критично, но полезно для безопасности ядра.

### 1.6 Выключение и сброс машины

- ~~**Завершение в headless-режиме.**~~ Сделано: после `HLT` эмулятор
  выходит с кодом 0, после неисправимого fault — с кодом 1; `--debug`
  выводит состояние CPU при остановке.
- ~~**Power/reset.**~~ Сделано: power-контроллер позволяет гостю выключить
  машину с кодом выхода или перезагрузить её.
- **Сброс с хоста.** Общий сброс CPU и устройств реализован в
  `motherboard_reset()` и вызывается power-контроллером. Горячей клавиши
  для сброса с хоста пока нет.

### Замеченная проблема: спекулятивная выборка из I/O

IF выбирает инструкции по `pc+4`, `pc+8` до того, как EX разрешит переход, и
делает это обычным `bus.read`. Если соседняя виртуальная страница отображена
на I/O с правом `X` (или программа выполняет код рядом с концом региона),
выборка по ложному пути прочитает регистр устройства. Чтение `UART DATA` или
`KBD DATA` при этом **снимает байт из FIFO**, хотя инструкция будет отменена.

Решение: выборка из I/O-региона (`0xFD000000`–`0xFDFFFFFF`) — это всегда
fetch bus error без обращения к устройству. Лучше сделать это на уровне шины
отдельным флагом «fetch» или отдельным методом `bus.fetch`, и записать правило
в спецификацию. Аналогично стоит запретить обход таблиц страниц по
I/O-адресам (сейчас в спецификации только предупреждение о побочных
эффектах).

**Исправлено.** В `bus_t` добавлен метод `fetch`: он читает только RAM и
ROM, а для I/O-региона возвращает bus error, не обращаясь к устройству.
Через него идут выборка в IF (fetch bus error) и обход таблиц страниц
(page fault). Правило записано в `INSTRUCTIONS.md` и `SPECIFICATION.md`.

| Перечисление устройств | нет | таблица устройств в ROM или ID-регистр в каждой I/O-странице (`+0xFFC`: тип и версия), чтобы ОС не хардкодила адреса |

**Исправлено.** Размеры слотов задаёт `--ram` (например, `--ram 4M,4M`,
до четырёх слотов), по умолчанию — 1MB в слоте 0.

## 4. Эмулятор (хост)

### 4.1 Конфигурация и запуск

- ~~**CLI.**~~ Сделано: разбираются `--rom`, `--ram`, `--clock`, `--hdd`,
  `--headless`, `--debug` и `--trace`.
- **Неиспользуемые поля конфигурации:** `make_dump`, `window_scale`,
  `step_mode` и `floppy_path`.
- ~~**Headless-режим.**~~ Сделано: работает без окна до `HLT` или power-off,
  возвращает код выхода гостя и используется автотестами и CI.

Подробности параметров запуска — в README.

### 4.2 Отладка

Сейчас вся диагностика — одна строка `warning` при halt по исключению. Нужно
(примерно в порядке полезности):

1. **Дамп состояния при остановке:** GPR, `pc`, CR, содержимое конвейера,
   `cycles`/`retired`.
2. **Трассировка** (`--trace`): адрес, слово, дизассемблированная инструкция
   и записанный регистр на каждую retired-инструкцию.
3. **Дизассемблер.** Он пригодится и в C (для трассировки), и в Python (для
   `asm.py`). Таблица форматов уже есть в `cpu_decode`.
4. **Пошаговый режим и точки останова:** поле `step_mode` уже заведено, а
   также watchpoints на адреса.
5. **Символы.** Загрузка листинга или symbol-файла из `asm.py -l`, чтобы
   показывать `puts+0x14` вместо голого адреса.
6. **GDB remote stub** (TCP): позволит пользоваться `gdb` или `lldb`, когда
   появится компилятор. В перспективе.
7. **Дамп памяти** (`make_dump`).

**Исправлено (1–3).** `cpu_dump` печатает в stderr состояние CPU: причину
остановки, `pc`, `cycles`/`retired`, линию IRQ, GPR, CR с расшифровкой
`STATUS`/`CAUSE`/`PTBR` и все четыре защёлки конвейера. После halt
конвейер больше не очищается, поэтому в `MEM/WB` видна инструкция,
которая остановила CPU. Дамп печатается всегда после неисправимого fault,
а с `--debug` — при любой остановке и при выходе. `--trace` пишет строку
на каждую инструкцию, дошедшую до WB: такт, адрес, слово, дизассемблер и
эффект (регистр, память, CR, `pc` после `IRET`) либо fault; взятое
прерывание — отдельной строкой. Дизассемблер есть в C
(`source/disasm.c`, для трассировки и дампа) и в Python
(`tools/disasm.py`, для образов). Синтаксис у них один и совпадает с
`asm.py`: вывод собирается обратно в те же байты, а слова, которые
ассемблер не может породить (данные, ненулевые reserved-биты), выводятся
как `.word`.

### 4.3 Производительность и точность времени

- **Нет индикатора скорости.** Не видно, успевает ли эмуляция за 48 MHz.
  `clock_update` ограничивает догон ста миллисекундами, и если хост не
  успевает, машина тихо замедляется. Нужен индикатор (MIPS, % от
  реального времени) в заголовке окна или в выводе.
- **Нет быстрого пути для `WFI`.** Сейчас цикл всё равно прогоняет все
  такты по одному. Можно пропускать такты до ближайшего события таймера.
- **Функциональный режим (опционально).** Можно добавить режим без
  конвейера (одна инструкция за вызов) для скорости, оставив конвейерный
  режим для точного тайминга.

### 4.4 Прочее

- **Сохранение состояния.** Snapshot и restore (CPU, RAM, устройства)
  пригодятся при отладке ОС.
- **Обработка ошибок I/O.** `rom_load` не проверяет результат `ftell` и
  `fread`.
- **README.** Нет инструкции по нативной сборке. Команда `dd ...` создаёт
  пустой ROM, но не объясняет, как собрать прошивку. Стоит добавить
  `cmake -S . -B build && cmake --build build` и
  `python3 tools/asm.py firmware/main.asm -o bin/firmware.rom`.
